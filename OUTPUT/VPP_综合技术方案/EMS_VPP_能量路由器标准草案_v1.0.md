## 1. 范围

### 1.1 标准定位

本规范定义了用于**虚拟电厂（VPP）场景下的本地化能量路由器（Energy Router）** 的技术架构、功能要求、通信接口、物理约束模型及安全规范。

### 1.2 适用场景

本规范适用于以下部署场景：

- **台区级VPP**：10kV/400V配电变压器台区内的分布式能源聚合与管理；
- **光储充一体化站点**：光伏、储能、电动汽车充电桩的本地协同控制；
- **微电网群**：多个邻近台区之间的能量路由与带宽共享；
- **工商业园区**：多租户、多业主共用母线的复杂能源管理场景。

### 1.3 目标设备形态

本规范定义的能量路由器以**边缘计算节点（Edge Node）** 为物理载体，可部署于：

- 工业级嵌入式网关（如基于ARM/x86的工控机）；
- 支持容器化部署的服务器；
- 集成于智能配电终端的一体化设备。

## 4. 系统架构

### 4.1 总体架构

能量路由器采用**三层物联网架构**，由**边缘计算层（Edge Layer）**、**云服务层（Cloud Layer）** 和**应用交互层（App Layer）** 组成。

```
┌─────────────────────────────────────────────────────────────┐
│                    应用交互层 (App Layer)                     │
│  ┌──────────────────────────────────────────────────────┐   │
│  │  OpenEMS UI / 第三方运维平台 / 移动端APP              │   │
│  │  功能：实时监控、参数配置、SOE查询、拓扑可视化        │   │
│  └──────────────────────┬───────────────────────────────┘   │
│                         │ JSON-RPC over WebSocket            │
├─────────────────────────┼───────────────────────────────────┤
│                    云服务层 (Cloud Layer)                     │
│  ┌──────────────────────────────────────────────────────┐   │
│  │  OpenEMS Backend / VPP聚合平台                       │   │
│  │  功能：多节点聚合、时序存储(InfluxDB)、元数据管理    │   │
│  │        (Odoo)、用户认证(OAuth2)、全局拓扑维护        │   │
│  └──────────────────────┬───────────────────────────────┘   │
│                         │ JSON-RPC over WebSocket (TLS)      │
├─────────────────────────┼───────────────────────────────────┤
│                    边缘计算层 (Edge Layer)                    │
│  ┌──────────────────────────────────────────────────────┐   │
│  │  能量路由器 (Energy Router Node)                     │   │
│  │  ┌──────────┐ ┌──────────┐ ┌──────────────────┐    │   │
│  │  │ 数据采集  │ │ 控制算法  │ │ 协议转换与路由   │    │   │
│  │  │ (Bridge)  │ │(Controller)│ │ (Router)         │    │   │
│  │  └────┬─────┘ └────┬─────┘ └────────┬─────────┘    │   │
│  │       │            │                │               │   │
│  │  ┌────▼────────────▼────────────────▼──────────┐   │   │
│  │  │  物理约束引擎 (Physical Constraint Engine)   │   │   │
│  │  │  热容量模型 / I²t积分 / 三相不平衡 / THD     │   │   │

└─────────────────────────────────────────────────────────────┘
```

### 4.2 能量交换机抽象模型

能量路由器在逻辑上抽象为**能源交换机（Energy Switch）**，其核心映射关系如下：

|    网络设备概念     | 能量路由器对应实现                 | 说明                                 |
| :-----------------: | ---------------------------------- | ------------------------------------ |
|   **端口 (Port)**   | 每个受控设备（充电桩、储能、光伏） | 通过ManagedEvcs/ManagedEss接口管理   |
|    **背板带宽**     | 台区变压器额定容量（季节修正后）   | 所有端口的总功率上限                 |
|    **MAC地址表**    | 设备拓扑邻居表                     | 基于电压相关性和NILM事件对账自动发现 |
|    **QoS优先级**    | L1-L4分级标签                      | 决定减载/限流的先后顺序              |
|    **路由决策**     | 本地控制器算法                     | 根据电价、物理约束、信用权重分配带宽 |
| **生成树协议(STP)** | 潮流冲突预防与带宽仲裁             | 防止多节点同时倒送电导致母线过载     |

### 4.3 数据流架构

能量路由器的数据流分为三个闭环：

**闭环一：实时控制环（毫秒级）**

```
传感器采样 → 物理约束校验 → 控制算法解算 → 指令下发 → 执行反馈
```

**闭环二：状态上报环（秒级）**

```
设备状态 → 数据聚合 → JSON-RPC推送 → 云端存储 → UI刷新
```

**闭环三：协同路由环（秒~分钟级）**

```
本地拓扑发现 → 邻居节点握手 → 带宽配额协商 → 路由表更新 → 云端同步
```

## 5. 功能要求

### 5.1 实时数据采集

能量路由器应具备以下数据采集能力：

| 采集类型 |    采样频率    | 数据项                                      |    接口协议     |
| -------- | :------------: | ------------------------------------------- | :-------------: |
| 电气量   | ≥1 kHz（推荐） | 三相电压、电流、有功/无功功率、功率因数     | Modbus TCP/RTU  |
| 电能质量 |     ≥1 kHz     | 谐波(THD)、电压偏差、频率偏差、三相不平衡度 | IEC 61000-4-30  |
| 设备状态 |      1 Hz      | 开关状态、告警码、运行模式                  |  Modbus / MQTT  |
| 环境量   |     0.1 Hz     | 环境温度（用于热容量修正）                  | Modbus / 4-20mA |
| 储能数据 |      1 Hz      | SOC、SOE、SOH、充放电循环次数               |  Modbus / CAN   |

**要求**：1 kHz采样数据应在边缘侧完成特征提取（FFT、RMS计算），仅将特征参数上传云端，原始波形按需本地缓存。

### 5.2 本地控制闭环

能量路由器应具备**断网独立运行**的本地控制能力，控制周期应≤1秒。

#### 5.2.1 控制算法框架

```
每个控制周期(Cycle)：
  阶段1：读取所有通道(Channel)实时数据
  阶段2：运行物理约束引擎（热容量、I²t、三相平衡、THD）
  阶段3：运行控制算法（削峰填谷、自发自用、电价跟踪）
  阶段4：生成各端口功率设定值(Setpoint)
  阶段5：通过WriteHandler下发指令
  阶段6：记录SOE日志
```

#### 5.2.2 设备分级标签（L1-L4）

能量路由器应对所有受控设备进行分级标签管理：

|  级别  | 名称                    | 定义                             | 减载策略                                   | 典型设备                         |
| :----: | ----------------------- | -------------------------------- | ------------------------------------------ | -------------------------------- |
| **L1** | 核心负荷 (Critical)     | 断电将导致人身安全或重大财产损失 | **永不减载**，即使母线热容量触顶           | 医疗设备、安防系统、生命维持负荷 |
| **L2** | 保障负荷 (Guaranteed)   | 需要持续供电但允许短时功率压缩   | **按比例限流**，最大压缩不超过30%          | 关键办公、冷链物流、数据中心     |
| **L3** | 可延时负荷 (Deferrable) | 可在时间维度上平移的负荷         | **优先减载**，可完全切断或调低至最小功率   | 电动汽车充电桩、储能充电         |
| **L4** | 机会负荷 (Opportunity)  | 非必要、可随时中断的负荷         | **首选切断**，一旦触发任何约束立即释放带宽 | 景观照明、非紧急广告牌           |

**标签管理规则**：

- 标签应在设备注册时由系统管理员分配；
- 能量路由器应通过NILM技术对标签进行**物理身份校验**，发现标签与实际负载特征不符时自动降级并告警；
- 标签可在运行时动态调整（如参与调频服务的L3设备临时提升至L2优先级）。

### 5.3 柔性减载策略

#### 5.3.1 减载触发条件

当以下任一条件满足时，能量路由器应启动减载流程：

1. **热容量越限**：当前功率超过变压器季节修正后的额定容量；
2. **I²t积分超阈值**：暂态过载的累积热量超过安全限值；
3. **电压质量恶化**：电压偏差超过±10%或THD超过8%；
4. **三相不平衡超标**：三相电流不平衡度超过15%；
5. **外部指令**：收到VPP云端或电网调度的减载指令。

#### 5.3.2 减载执行次序

减载应按照以下次序分步执行，防止同步动作导致的电压过冲：

| 步骤 | 动作               |   延迟    | 目标设备             |    功率变化率限制    |
| :--: | ------------------ | :-------: | -------------------- | :------------------: |
|  1   | 切断L4级设备       |  T+0 ms   | 景观照明、非关键负荷 |   不限（瞬时切断）   |
|  2   | L3级设备限流至50%  |  T+50 ms  | 充电桩、储能充电     |   ≤20%额定功率/秒    |
|  3   | L3级设备限流至最小 | T+200 ms  | 充电桩、储能充电     |   ≤10%额定功率/秒    |
|  4   | L2级设备压缩至70%  | T+500 ms  | 关键办公、冷链       |    ≤5%额定功率/秒    |
|  5   | 紧急全切（保留L1） | T+1000 ms | 所有非L1设备         | 不限（仅限极端情况） |

**要求**：

- 每个步骤之间应引入基于节点ID哈希的**随机延迟（Jitter）**，偏移范围为0~50ms，防止多台区同步动作；
- 每个步骤执行后应通过实时通道验证功率是否真实下降，若未响应则在10ms内执行下一级动作；
- 减载完成后应生成完整的SOE记录。

### 5.4 预测与基线

#### 5.4.1 负荷/光伏预测

能量路由器应具备未来24小时的负荷和光伏出力预测能力：

| 预测类型       | 时间分辨率 | 预测时长 | 算法建议                |
| -------------- | :--------: | :------: | ----------------------- |
| 超短期负荷预测 |   5分钟    |  1小时   | LSTM + 物理约束         |
| 短期负荷预测   |   15分钟   |  24小时  | 时序分解 + 相似日匹配   |
| 光伏出力预测   |   15分钟   |  24小时  | 数值天气预报 + 物理模型 |
| 灵活性预测     |   15分钟   |  24小时  | 基于设备状态的概率模型  |

#### 5.4.2 基线计算

能量路由器应实时计算负荷基线，用于VPP结算依据：

- **基线定义**：在无VPP调控指令情况下，台区在相同外部条件下的预期负荷曲线；
- **计算方法**：取最近10个相似日（同类型日、同天气条件）的负荷数据，剔除最高和最低值后取平均；
- **更新频率**：每日自动更新，支持人工修正；
- **存储要求**：本地至少存储30天的历史基线数据。

### 5.5 离线自治

当能量路由器与云端连接中断时，应自动切换至**离线自治模式**：

| 功能           |  在线模式  |          离线模式          |
| -------------- | :--------: | :------------------------: |
| 本地控制闭环   | ✓ 正常运行 |         ✓ 正常运行         |
| 云端指令接收   |     ✓      | ✗（使用最后一次有效指令）  |
| 拓扑发现与同步 | ✓ 实时同步 | ✓ 本地缓存，恢复后断点续传 |
| 带宽预借       | ✓ 云端授权 |  ✓ 基于信用权重的本地预借  |
| SOE记录        | ✓ 实时上传 | ✓ 本地缓存，恢复后批量上传 |
| 基线更新       | ✓ 云端辅助 |       ✓ 本地独立计算       |
| 固件升级       |     ✓      |             ✗              |

**离线恢复**：网络恢复后，能量路由器应在30秒内完成与云端的全量数据同步。

### 5.6 NILM与AnomAlert融合

#### 5.6.1 NILM功能要求

能量路由器应集成非侵入式负载监测（NILM）能力：

- **采样要求**：≥1 kHz，三相电压/电流同步采样；
- **识别能力**：至少能识别充电桩启动、储能充放电、大型电机启停、空调压缩机等典型设备事件；
- **识别延迟**：从事件发生到输出识别结果应≤200ms；
- **识别准确率**：在典型台区环境下应≥90%。

#### 5.6.2 AnomAlert异常识别

借鉴AnomAlert的机械诊断逻辑，能量路由器应具备以下异常识别能力：

| 异常类型         | 检测方法                  | 响应动作                             |
| ---------------- | ------------------------- | ------------------------------------ |
| 设备启动涌流异常 | 电流上升斜率(di/dt)超阈值 | 标记设备为"亚健康"，降低其调度优先级 |
| 谐波特征突变     | 特定次谐波幅值偏离基线    | 触发电能质量告警，限制非线性负载接入 |
| 接触不良/微弧    | 高频噪声分量异常          | 触发设备检修告警，记录SOE            |
| 电容老化         | 功率因数偏移特征          | 建议更换设备，调整无功补偿策略       |
| 三相不平衡恶化   | 中性点电流持续上升        | 触发负载迁移或限流                   |

#### 5.6.3 物理身份校验

能量路由器应利用NILM技术对设备的分级标签进行**物理身份校验**：

```
流程：
1. 设备注册时记录其电气指纹（V-I轨迹、谐波特征、启动斜率）
2. 运行时持续监测该设备的实际电气特征
3. 若实际特征与注册指纹偏差超过阈值：
   a. 自动降低该设备的信用权重
   b. 触发告警："设备标签与物理身份不符"
   c. 将该设备从高优先级队列移除
```

|  Bit位  | 用途           | 说明                                    |

## 7. 物理约束模型

### 7.1 变压器热容量模型

#### 7.1.1 额定容量与季节修正

能量路由器应维护变压器的动态额定容量，考虑环境温度的修正：

$$P_{max}(T) = P_{rated} \times k_T(T)$$

其中：

- $P_{rated}$：变压器铭牌额定容量（kW）
- $k_T(T)$：温度修正系数，与环境温度 $T$（°C）相关

**温度修正系数参考值**：

| 环境温度 | 修正系数 $k_T$ | 说明     |
| :------: | :------------: | -------- |
|  ≤ 20°C  |      1.00      | 标准工况 |
|   25°C   |      0.97      | 轻度降额 |
|   30°C   |      0.93      | 中度降额 |
|   35°C   |      0.88      | 显著降额 |
|   40°C   |      0.82      | 严重降额 |
|  ≥ 45°C  |      0.75      | 极限降额 |

**要求**：能量路由器应接入环境温度传感器，每15分钟更新一次 $P_{max}$ 值。

#### 7.1.2 热累积模型

能量路由器应实时计算变压器的热累积状态：

$$H(t) = \int_{t-T_{window}}^{t} \left( \frac{P(\tau)}{P_{max}(T)} \right)^2 d\tau$$

其中：

- $H(t)$：当前热累积值
- $T_{window}$：热时间常数（典型值：30分钟）
- $P(\tau)$：实时功率

**阈值定义**：

- $H(t) < 0.7$：正常状态
- $0.7 \leq H(t) < 0.85$：预警状态，启动L3/L4减载
- $0.85 \leq H(t) < 1.0$：严重状态，启动L2减载
- $H(t) \geq 1.0$：紧急状态，启动全量减载

### 7.2 暂态过载约束（I²t积分）

能量路由器应监控短时过载的累积效应：

$$I^2t = \int_{t_0}^{t} I(\tau)^2 d\tau \leq I^2t_{limit}$$

**阈值参考**：

- 短时过载（<10秒）：允许1.5倍额定电流
- 长时过载（>10秒）：不允许超过额定电流
- I²t积分上限：由变压器厂家提供，默认值为额定电流平方×120秒

**应用逻辑**：

- 正常电机启动冲击（<200ms）：允许，记录SOE
- 频繁启动（>5次/小时）：触发告警，降低该设备信用权重
- 持续过载：触发减载

### 7.3 电压质量约束

#### 7.3.1 电压偏差

|   指标   | 正常范围 | 预警阈值 | 动作阈值 |
| :------: | :------: | :------: | :------: |
| 电压偏差 |   ±7%    |   ±10%   |   ±15%   |
| 频率偏差 | ±0.2 Hz  | ±0.5 Hz  | ±1.0 Hz  |

**响应策略**：

- 电压偏差超过预警阈值：启动L3/L4减载
- 电压偏差超过动作阈值：启动全量减载（保留L1）
- 频率偏差超过预警阈值：启动斜率限流（≤10%额定功率/秒）

#### 7.3.2 谐波约束（THD）

|     谐波类型      | 正常范围 | 预警阈值 | 动作阈值 |
| :---------------: | :------: | :------: | :------: |
| 总谐波畸变率(THD) |   <5%    |  5%~8%   |   >8%    |
|      3次谐波      |   <3%    |  3%~5%   |   >5%    |
|      5次谐波      |   <3%    |  3%~5%   |   >5%    |
|      7次谐波      |   <2%    |  2%~4%   |   >4%    |

**响应策略**：

- THD超过预警阈值：标记谐波源设备，降低其调度优先级
- THD超过动作阈值：限制非线性负载接入，启动滤波补偿

### 7.4 三相不平衡约束

|       指标       | 正常范围 | 预警阈值 | 动作阈值 |
| :--------------: | :------: | :------: | :------: |
| 三相电流不平衡度 |   <10%   | 10%~15%  |   >15%   |
| 三相电压不平衡度 |   <2%    |  2%~3%   |   >3%    |

**不平衡度计算公式**：

$$U_{unbalance} = \frac{I_{max} - I_{min}}{I_{avg}} \times 100\%$$

**响应策略**：

- 超过预警阈值：记录SOE，标记重载相
- 超过动作阈值：
  1. 限制重载相的新增负载接入
  2. 引导支持单相/三相切换的设备迁移至轻载相
  3. 触发负载迁移告警上报云端

### 7.5 物理约束仲裁优先级

当多个物理约束同时触发时，能量路由器应按照以下优先级执行仲裁：

|  优先级   | 约束类型      | 说明           |
| :-------: | ------------- | -------------- |
| 1（最高） | 电压/频率偏差 | 系统稳定性优先 |
|     2     | I²t暂态过载   | 防止设备热损坏 |
|     3     | 热容量越限    | 防止变压器过载 |
|     4     | 三相不平衡    | 防止中性点偏移 |
|     5     | 谐波(THD)     | 电能质量管理   |

## 8. 协同与路由

### 8.1 多节点拓扑发现

#### 8.1.1 电压相关性发现

能量路由器应通过电压波动相关性分析自动发现物理邻近节点：

**算法逻辑**：

1. 每个节点实时记录本台区电压波形（1 Hz采样）
2. 节点通过局域网广播自己的"电压波动指纹"（过去60秒的ΔV曲线）
3. 接收节点计算与本节点电压波形的互相关函数
4. 若相关系数 $r > 0.85$，判定为同一10kV支路上的邻近节点

**相关系数阈值**：
| 相关系数 $r$ | 判定结果 | 电气距离 |
|:------------:|:--------:|:--------:|
| $r \geq 0.95$ | 同一台区或极邻近 | 极近 |
| $0.85 \leq r < 0.95$ | 同一10kV支路 | 邻近 |
| $0.70 \leq r < 0.85$ | 同一变电站不同支路 | 较远 |
| $r < 0.70$ | 不同变电站 | 非邻近 |

#### 8.1.2 NILM事件对账

能量路由器应通过NILM事件的跨节点对账确认拓扑关系：

```
流程：
1. 节点A识别到本地大型设备启动事件（如充电桩7kW启动）
2. 节点A广播事件通知（含时间戳、事件特征哈希）
3. 节点B在本地检测到"影子事件"（跨台区扰动）
4. 节点B比对事件特征哈希，若匹配则确认与A的物理连接
5. 影子事件的强度（幅值衰减比）作为电气距离的度量
```

#### 8.1.3 拓扑版本号管理

每个能量路由器应维护一个**拓扑版本号**：

| 版本号变化 | 含义         | 触发条件                                                     |
| :--------: | ------------ | ------------------------------------------------------------ |
|   初始值   | 首次部署     | 设备上电                                                     |
|     +1     | 拓扑变更     | 发现新邻居 / 邻居离线 / 电压相关性系数突变 > 0.15            |
|     +1     | 物理切改     | NILM事件对账发现电气特征永久性变化（如变压器更换、线路改造） |
|    重置    | 云端强制同步 | 收到云端 `resetTopology` 指令                                |

**同步机制**：

- 拓扑版本号变更后，节点应在1秒内向所有邻居节点广播版本号更新；
- 邻居节点收到更新后，若发现版本号不一致，发起拓扑对账请求；
- 云端定期（默认每15分钟）对所有在线节点进行拓扑版本号一致性检查。

### 8.2 带宽配额交换

#### 8.2.1 带宽配额定义

带宽配额（Bandwidth Quota）是能量路由器在物理约束下可分配给各端口的最大功率限额：

$$Q_{total} = P_{max}(T) - P_{reserved} - P_{loss}$$

其中：

- $Q_{total}$：当前可分配的总带宽配额
- $P_{max}(T)$：变压器季节修正后的额定容量
- $P_{reserved}$：为L1/L2级负荷预留的保底功率
- $P_{loss}$：线路损耗预留

#### 8.2.2 配额交换协议

邻近节点之间应通过以下协议进行带宽配额交换：

```
请求方(Request) → 广播"带宽需求声明"（含需求量、时间窗口、信用权重）
    ↓
响应方(Response) → 评估自身剩余配额，返回"可出让配额"（含出让量、代价因子）
    ↓
请求方(Request) → 选择最优响应方，发送"配额确认"
    ↓
双方确认 → 更新本地路由表，记录SOE
```

**消息格式**：

```json
{
  "method": "bandwidthExchange",
  "params": {
    "__header__": {
      "protocol_version": "1.0",
      "target_id": "TA-001",
      "priority_tag": "L3",
      "reserved_byte": "0x00",
      "timestamp": 1715218372000,
      "ttl": 3000,
      "topology_version": 42,
      "credit_weight": 0.85
    },
    "exchange_type": "REQUEST",
    "required_power_w": 50000,
    "time_window_ms": 600000,
    "max_cost_factor": 0.15,
    "reason": "EV_CHARGING_PEAK"
  }
}
```

#### 8.2.3 信用权重与预借机制

能量路由器应基于历史行为维护每个邻居节点的**信用权重**：

| 信用权重范围 | 等级   | 预借权限              | 更新条件                     |
| :----------: | ------ | --------------------- | ---------------------------- |
|  0.9 ~ 1.0   | 优秀   | 可预借最大50%额定带宽 | 连续100次减载指令100%响应    |
|  0.7 ~ 0.9   | 良好   | 可预借最大30%额定带宽 | 连续50次减载指令≥95%响应     |
|  0.5 ~ 0.7   | 一般   | 可预借最大15%额定带宽 | 连续20次减载指令≥90%响应     |
|  0.3 ~ 0.5   | 较差   | 不可预借，需实时确认  | 减载响应率<90%               |
|  0.0 ~ 0.3   | 不可信 | 拒绝任何带宽交换请求  | 减载响应率<80%或存在违约记录 |

**信用权重衰减规则**：

- 每次未响应减载指令：权重减0.05
- 每次超额预借导致母线风险：权重减0.10
- 每次成功协助邻居减载：权重加0.01（上限1.0）
- 权重每日自动恢复0.01（不超过历史最高值）

### 8.3 多路径路由与虚拟切片

#### 8.3.1 多路径冗余

能量路由器应维护多条到目标节点的逻辑路径，实现带宽分配的冗余：

```
主路径：TA-001 → TA-002 → TA-003（代价：0.05）
备路径1：TA-001 → TA-004 → TA-003（代价：0.12）
备路径2：TA-001 → TA-005 → TA-006 → TA-003（代价：0.25）
```

**路径切换条件**：

- 主路径节点信用权重降至0.5以下
- 主路径物理约束触发预警
- 主路径节点离线超过5秒

#### 8.3.2 虚拟切片

能量路由器应支持在物理拓扑不变的情况下，通过逻辑切片实现资源分层：

| 切片ID | 名称         | 保留带宽比例 | 用途                        | 优先级 |
| :----: | ------------ | :----------: | --------------------------- | :----: |
|  S-01  | 生命线切片   |     20%      | L1级核心负荷保底            |  最高  |
|  S-02  | 商业保障切片 |     30%      | L2级商业负荷保障            |   高   |
|  S-03  | 灵活调度切片 |     30%      | L3级可延时负荷（充电桩等）  |   中   |
|  S-04  | 机会切片     |     20%      | L4级机会负荷 + 跨台区交换池 |   低   |

**切片管理规则**：

- 切片带宽比例可在运行时动态调整（需云端授权）
- 当某切片带宽闲置超过15分钟，自动释放至公共池
- 紧急状态下，高优先级切片可抢占低优先级切片的带宽

### 8.4 潮流冲突预防

#### 8.4.1 倒送电冲突检测

当多个节点同时向10kV母线倒送电时，能量路由器应检测并预防潮流冲突：

**检测逻辑**：

1. 节点监测本台区功率流向（正向=从电网取电，反向=向电网送电）
2. 当检测到反向功率且邻近节点也处于反向状态时，触发冲突检测
3. 计算所有反向节点的总功率，若超过母线允许的反向容量，启动仲裁

#### 8.4.2 带宽仲裁协议

```
冲突检测 → 所有冲突节点进入"仲裁模式"
    ↓
各节点上报：当前反向功率、可削减量、削减代价
    ↓
仲裁节点（由拓扑版本号最高的节点担任）计算最优分配方案
    ↓
下发仲裁结果：各节点按比例削减反向功率
    ↓
执行并反馈 → 记录SOE
```

**仲裁原则**：

- 优先保障L1/L2级负荷的本地用电（不允许反向送电时牺牲本地负荷）
- 按"边际削减成本"从低到高排序，优先削减成本低的节点
- 仲裁结果应在100ms内完成下发和执行

### 9.1 SOE顺序事件记录

#### 9.1.1 SOE记录规范

能量路由器应对所有关键事件生成带高精度时间戳的SOE记录：

**SOE记录字段定义**：

| 字段            | 类型    | 说明                                                  |

| 事件类型          | 触发条件                           | 记录优先级 |
| ----------------- | ---------------------------------- | :--------: |
| 设备上下线        | 设备注册/注销/离线                 |     高     |
| 物理约束触发      | 热容量/I²t/电压/THD/三相不平衡越限 |     高     |

| 带宽交换          | 配额请求/确认/执行                 |     中     |
| 云端指令接收      | 收到云端控制指令                   |     中     |
| 离线/在线切换     | 与云端连接状态变化                 |     高     |
| NILM事件识别      | 识别到大型设备启动/停止            |     中     |
| AnomAlert异常告警 | 检测到设备异常指纹                 |     高     |
| 信用权重变更      | 权重变化超过0.05                   |     低     |
| 固件升级          | 固件升级开始/完成/失败             |     中     |

#### 9.1.3 SOE存储与同步

| 存储层级 | 存储位置       | 存储周期  | 用途                   |
| :------: | -------------- | :-------: | ---------------------- |
|  L1缓存  | 内存环形缓冲区 | 最近1小时 | 实时查询与故障快速定位 |
|  L2存储  | 本地磁盘       |   30天    | 离线期间的本地存证     |
|  L3存储  | 云端InfluxDB   |   永久    | 长期审计与合规分析     |

**同步策略**：

- 在线模式下：SOE实时推送至云端（延迟≤1秒）
- 离线模式下：SOE缓存至本地，恢复连接后30秒内批量上传
- 云端收到SOE后返回确认，本地删除已确认的记录

### 9.2 影子折旧模型

#### 9.2.1 资产寿命损耗计算

能量路由器应基于设备运行工况计算资产寿命损耗：

$$D_{total} = \sum_{i=1}^{n} (w_1 \times C_{cycle,i} + w_2 \times O_{overload,i} + w_3 \times T_{thermal,i})$$

其中：

- $D_{total}$：总折旧系数（0.0~1.0，1.0表示寿命耗尽）
- $C_{cycle,i}$：第i次充放电循环的折旧贡献
- $O_{overload,i}$：第i次暂态过载的折旧贡献
- $T_{thermal,i}$：第i次高温运行的折旧贡献
- $w_1, w_2, w_3$：权重系数（默认值：0.5, 0.3, 0.2）

#### 9.2.2 折旧报告

能量路由器应定期生成资产折旧报告：

| 报告类型     | 生成频率 | 内容                                                 |
| ------------ | :------: | ---------------------------------------------------- |
| 日报         |   每日   | 当日充放电循环次数、过载次数、最高温度、当日折旧增量 |
| 周报         |   每周   | 本周折旧趋势、异常事件汇总、设备健康度评分           |
| 月报         |   每月   | 本月总折旧、剩余寿命预测、维护建议                   |
| 事件触发报告 | 事件触发 | 当折旧系数超过0.8时触发，建议设备更换或降额运行      |

### 9.3 审计追踪

#### 9.3.1 审计数据要求

能量路由器应提供完整的审计追踪能力，满足电网合规性要求：

| 审计维度 | 数据要求                                                  | 保留期限 |
| -------- | --------------------------------------------------------- | :------: |
| 操作审计 | 记录所有配置变更、指令下发、参数修改的操作者、时间、内容  |   永久   |
| 事件审计 | 所有SOE事件的完整记录                                     |   永久   |
| 数据审计 | 所有上报数据的原始副本（含时间戳和版本号）                |   2年    |
| 安全审计 | 所有登录尝试、权限变更、TLS握手记录                       |   2年    |
| 合规审计 | 基线数据、灵活性聚合数据、减载执行记录（用于VPP结算对账） |   5年    |

#### 9.3.2 审计数据导出

能量路由器应支持以下审计数据导出方式：

- **自动推送**：按配置周期自动将审计数据推送至云端归档

### 10.3 控制安全

#### 10.3.1 本地优先仲裁

能量路由器应遵循**Edge-first（本地优先）** 的安全原则：

```
云端指令到达 → 物理约束引擎校验
    ↓
校验通过 → 执行指令
校验不通过 → 记录SOE："云端指令被本地约束拦截"
    ↓
向云端返回执行结果（含拦截原因）
```

**拦截条件**：

- 云端指令会导致物理约束越限
- 云端指令与本地保护逻辑冲突
- 云端指令的TTL已过期
- 云端指令的拓扑版本号与本地不一致

#### 10.3.2 指令合法性校验

所有接收到的控制指令应经过以下校验：

| 校验项     | 说明                                                         |
| ---------- | ------------------------------------------------------------ |
| 来源校验   | 验证指令发送方的身份和权限                                   |
| 完整性校验 | 验证指令在传输过程中未被篡改（TLS层已保证）                  |
| 时效性校验 | 验证指令的TTL是否过期                                        |
| 合理性校验 | 验证指令参数是否在合理范围内（如功率设定值不超过设备额定值） |
| 一致性校验 | 验证指令的拓扑版本号与本地一致                               |
| 冲突校验   | 验证指令不与当前正在执行的指令冲突                           |

#### 10.3.3 紧急切断

在极端情况下，能量路由器应支持**紧急切断（Emergency Shutdown）**：

**触发条件**：

- 检测到金属性短路特征（di/dt > 1000 A/s）
- 检测到电弧故障特征
- 收到电网调度的紧急切断指令（带最高优先级标志）
- 本地保护继电器动作信号

**执行要求**：

- 紧急切断应**越过所有减载次序**，在1ms内直接切断所有非L1级设备
- 紧急切断后应生成最高优先级的SOE记录
- 紧急切断后需人工确认才能恢复供电

### 10.4 数据安全

| 安全要求 | 规范                                                   |
| -------- | ------------------------------------------------------ |
| 数据加密 | 本地存储的敏感数据（证书、密钥、用户凭证）应加密存储   |
| 数据脱敏 | NILM采集的用户行为数据应在本地完成脱敏处理后再上传云端 |
| 数据备份 | 关键配置数据和SOE记录应支持本地和云端双重备份          |
| 数据销毁 | 设备退役时，应支持安全擦除所有本地存储数据             |
| 隐私保护 | 不得将未经脱敏的用户用电数据用于非授权用途             |
