## 1. 范围与规范性引用文件

### 1.1 范围

本标准规定了VPP 2.0本地能量管理系统（EMS）的架构设计、通信协议、调度算法、物理约束、安全合规和互操作要求。适用于：

- 分布式能源（DER）聚合商
- 充电桩运营平台
- 工商业储能系统
- 台区级能源管理节点
- 虚拟电厂（VPP）边缘计算节点

### 1.2 规范性引用文件

- IEC 61850: 电力自动化通信网络和系统
- IEC 60870-5-104: 远动设备及系统传输规约
- IEC 61000-4-30: 电能质量测量方法
- IEEE 1547: 分布式能源并网标准
- OCPP 1.6J/2.0.1: 充电桩通信协议
- Modbus TCP/RTU: 工业现场总线协议
- JSON-RPC 2.0: 远程过程调用协议
- OAuth 2.0: 授权框架
- TLS 1.3: 传输层安全协议

## 2. 术语与定义

### 2.1 核心术语

| 术语                           | 定义                                                                                |
| ------------------------------ | ----------------------------------------------------------------------------------- |
| **能源交换机 (Energy Switch)** | 将EMS节点抽象为电力网络智能交换节点的架构范式，具备端口管理、带宽分配、路由决策能力 |
| **VPP 2.0**                    | 具备预测能力、经济博弈能力和合规结算能力的第二代虚拟电厂                            |
| **台区 (Transformer Area)**    | 配电变压器供电区域，是EMS调度的基本物理单元                                         |
| **带宽 (Bandwidth)**           | 台区变压器或线路的可用功率容量，类比网络交换机的背板带宽                            |
| **NILM**                       | 非侵入式负载监测，通过总线电流/电压特征反推设备类型和状态                           |
| **SOE**                        | 顺序事件记录，带毫秒级时间戳的事件链记录，用于故障追溯                              |
| **头部识别码**                 | 消息头部中用于寻址和标识的结构化字段                                                |
| **分级标签**                   | 设备重要程度的分级标识，用于QoS调度决策                                             |

### 2.2 设备分级标签定义

| 级别   | 名称                  | 代表设备                     | 调度策略   |
| ------ | --------------------- | ---------------------------- | ---------- |
| **L1** | 关键级 (Critical)     | 居民生活、医疗监控、公共安防 | 永不减载   |
| **L2** | 保障级 (Guaranteed)   | 关键办公、冷链物流           | 按比例限流 |
| **L3** | 可延时级 (Deferrable) | 电动车充电、储能充电         | 优先减载   |
| **L4** | 随机级 (Opportunity)  | 景观灯光、非紧急负荷         | 首选切断   |

### 2.3 节点角色定义

| 角色      | 名称     | 职责                               |
| --------- | -------- | ---------------------------------- |
| **Root**  | 根节点   | 全局调度协调、路由表维护、带宽仲裁 |
| **Relay** | 中继节点 | 局部拓扑发现、指令转发、数据聚合   |
| **Leaf**  | 叶子节点 | 设备接入、本地控制、数据采集       |

## 3. 核心架构范式

### 3.1 能源交换机模型

VPP_EMS采用"能源交换机"（Energy Switch）作为核心架构范式。EMS节点被抽象为电力网络的智能交换节点，具备以下核心能力：

| 交换机概念               | 电力系统映射 | 功能描述                                             |
| ------------------------ | ------------ | ---------------------------------------------------- |
| **端口 (Port)**          | 设备接口     | 每个接入设备（充电桩、储能、逆变器）视为一个逻辑端口 |
| **背板带宽 (Backplane)** | 台区额定功率 | 变压器容量决定节点的最大总吞吐量                     |
| **MAC地址表**            | 设备指纹库   | NILM识别的设备特征指纹，用于身份确认                 |
| **QoS优先级**            | 分级标签     | L1-L4分级决定带宽分配优先级                          |
| **路由表**               | 电力路由表   | 节点间拓扑关系和路由代价                             |
| **流量整形**             | 斜率滤波     | 功率变化率控制，防止电压冲击                         |
| **拥塞控制**             | 协同减载     | 带宽不足时的有序减载机制                             |

### 3.2 数据流与控制流分离

系统严格分离数据平面（Data Plane）和控制平面（Control Plane）：

```
┌─────────────────────────────────────────────────────────┐
│                    控制平面 (Control Plane)               │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐ │
│  │调度指令  │  │策略配置  │  │紧急减载  │  │拓扑同步  │ │
│  └──────────┘  └──────────┘  └──────────┘  └──────────┘ │
│  优先级: 最高    确定性延迟: <10ms                        │
├─────────────────────────────────────────────────────────┤
│                    数据平面 (Data Plane)                  │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐ │
│  │设备状态  │  │时序数据  │  │历史数据  │  │事件日志  │ │
│  └──────────┘  └──────────┘  └──────────┘  └──────────┘ │
│  优先级: 普通    带宽: 尽力而为                           │
└─────────────────────────────────────────────────────────┘
```

### 3.3 拓扑发现机制

节点间拓扑发现采用三种互补机制：

1. **电压相关性分析**：物理位置越近的节点，10kV侧电压波动相关性越高
2. **NILM事件对账**：节点间同步观测到的电力扰动事件，确认物理连接关系
3. **电力载波RSSI**：通过电力线注入识别信号，测量信号强度推算电气距离

### 3.4 路由表维护规范

路由表采用"本地发现+云端同步"的混合维护机制：

- **本地维护**：Edge节点维护热数据（当前物理连接最紧密的邻居）
- **云端同步**：Backend拼接全局拓扑，维护冷数据和资产数据
- **版本号机制**：物理线路变动时，Edge节点申请更新拓扑版本号
- **冲突处理**：以Edge节点的实时电气感知为最高优先级

## 4. 三层架构规范

### 4.1 架构总览

```
┌─────────────────────────────────────────────────────────────┐
│                    OpenEMS UI (应用展现层)                    │
│  可视化监控 | 配置管理 | 调试工具 | 报表分析                  │
├─────────────────────────────────────────────────────────────┤
│                    OpenEMS Backend (云端服务层)               │
│  数据聚合 | 元数据管理 | 多租户 | 历史存储 | 全局调度        │
├─────────────────────────────────────────────────────────────┤
│                    OpenEMS Edge (现场控制层)                  │
│  本地控制 | 硬件驱动 | 离线自治 | 实时解算 | 协议适配       │
└─────────────────────────────────────────────────────────────┘
```

### 4.2 Edge（现场控制层）

**核心职责：**

- 毫秒级本地控制算法执行
- 硬件设备驱动和协议适配（Modbus/MQTT/OCPP）
- 离线自治运行（断网不中断控制）
- NILM实时分析和设备指纹识别
- SOE顺序事件记录

**技术要求：**

- 控制周期 ≤ 1秒
- 离线运行时间 ≥ 72小时
- 支持 ≥ 100个设备同时接入
- 本地日志存储 ≥ 30天

### 4.3 Backend（云端服务层）

**核心职责：**

- 多Edge节点数据聚合和持久化
- 元数据管理和设备资产登记
- 用户身份认证和权限管理
- 全局拓扑维护和路由表同步
- 历史数据分析和报表生成

**技术要求：**

- 支持 ≥ 10,000个Edge节点同时在线
- 时序数据写入吞吐量 ≥ 100万点/秒
- 元数据查询响应时间 ≤ 100ms
- 支持多租户隔离

### 4.4 UI（应用展现层）

**核心职责：**

- 实时功率流向可视化
- 设备状态监控和告警
- 调度策略配置和下发
- 历史数据查询和图表展示
- 现场调试和诊断工具

**技术要求：**

- 数据刷新延迟 ≤ 1秒
- 支持本地WiFi直连调试模式
- 支持PWA离线缓存
- 支持多语言界面

## 5. 通信协议与数据模型

### 5.1 JSON-RPC通信协议

所有层间通信采用JSON-RPC 2.0协议，支持三种消息格式：

#### 5.1.1 请求格式 (Request)

```json
{
  "jsonrpc": "2.0",
  "method": "setPowerLimit",
  "params": {
    "target_id": "TA001-BR01-EV01",
    "power_limit": 7000,
    "ramp_rate": 500,
    "priority": "L3"
  },
  "id": "msg_001"
}
```

#### 5.1.2 响应格式 (Response)

```json
{
  "jsonrpc": "2.0",
  "result": {
    "status": "accepted",
    "execution_time": 45,
    "actual_power": 7000
  },
  "id": "msg_001"
}
```

#### 5.1.3 通知格式 (Notification)

```json
{
  "jsonrpc": "2.0",
  "method": "eventReport",
  "params": {
    "event_type": "LOAD_SHED",
    "timestamp": 1683590400000,
    "target_id": "TA001-BR01-EV01",
    "reason": "THERMAL_OVERLOAD"
  }
}
```

### 5.2 标准方法集

| 方法名              | 方向         | 描述               |
| ------------------- | ------------ | ------------------ |
| `deviceRegister`    | Edge→Backend | 设备注册和身份认证 |
| `dataReport`        | Edge→Backend | 时序数据上报       |
| `setPowerLimit`     | Backend→Edge | 功率限制指令下发   |
| `setConfig`         | Backend→Edge | 配置参数同步       |
| `eventReport`       | Edge→Backend | 事件和告警上报     |
| `queryHistoricData` | UI→Backend   | 历史数据查询       |
| `subscribeChannel`  | UI→Edge      | 实时数据订阅       |
| `topologySync`      | Edge↔Edge    | 拓扑信息同步       |

### 5.3 头部识别码规范

消息头部识别码（Addressing Header）采用8字节结构：

```
┌─────────┬─────────┬─────────┬─────────┬─────────┬─────────┬─────────┬─────────┐
│ 台区ID  │ 台区ID  │ 台区ID  │ 台区ID  │ 支路ID  │ 支路ID  │ 设备类别 │ 保留字节 │
│  Byte0  │  Byte1  │  Byte2  │  Byte3  │  Byte4  │  Byte5  │  Byte6  │  Byte7  │
└─────────┴─────────┴─────────┴─────────┴─────────┴─────────┴─────────┴─────────┘
```

**字段定义：**

- **台区ID (4B)**：全局唯一台区标识符
- **支路ID (2B)**：台区内支路编号
- **设备类别 (1B)**：设备类型编码（0x01=充电桩, 0x02=储能, 0x03=光伏, 0x04=电表, 0xFF=广播）
- **保留字节 (1B)**：未来扩展用途

**保留字节扩展位定义：**

| 位      | 用途         | 描述                |
| ------- | ------------ | ------------------- |
| Bit 0   | 绿色能源标识 | 1=当前使用绿电      |
| Bit 1   | 辅助服务标识 | 1=正在参与调频/调峰 |
| Bit 2   | V2G属性      | 1=支持反向放电      |
| Bit 3   | 碳配额标签   | 1=携带碳配额        |
| Bit 4-7 | 预留         | 未来扩展            |

**寻址模式：**

- **单播**：精确匹配台区ID+支路ID+设备类别
- **组播**：匹配台区ID+支路ID，设备类别=0x00
- **广播**：台区ID=0xFFFFFFFF

### 5.4 设备分级标签规范

#### 5.4.1 静态标签定义

| 级别 | 编码 | 减载优先级 | 带宽保障 | 典型设备                     |
| ---- | ---- | ---------- | -------- | ---------------------------- |
| L1   | 0x01 | 永不减载   | 100%     | 居民照明、医疗设备、安防系统 |
| L2   | 0x02 | 第3批次    | ≥70%     | 办公设备、冷链、数据中心     |
| L3   | 0x03 | 第2批次    | ≥30%     | 充电桩、储能充电、热水器     |
| L4   | 0x04 | 第1批次    | ≥0%      | 景观灯、广告牌、非紧急设备   |

#### 5.4.2 动态标签调整机制

设备标签可根据以下因素动态调整：

1. **信用评分**：历史响应速度快的设备可获得标签升级
2. **NILM验证**：实际运行特征与标签声明不符时，自动降级
3. **辅助服务状态**：正在参与电网调频/调峰的设备临时升级
4. **紧急状态**：系统进入应急模式时，所有非L1设备降级

## 6. 调度算法与优化引擎

### 6.1 预测模型规范

#### 6.1.1 预测类型与精度要求

| 预测类型     | 预测周期     | 精度要求   | 更新频率 |
| ------------ | ------------ | ---------- | -------- |
| 光伏出力预测 | 超短期(5min) | MAE < 10%  | 每5分钟  |
| 光伏出力预测 | 短期(24h)    | MAE < 15%  | 每小时   |
| 负荷预测     | 超短期(5min) | MAPE < 10% | 每5分钟  |
| 负荷预测     | 短期(24h)    | MAPE < 15% | 每小时   |
| 电价预测     | 短期(24h)    | MAPE < 20% | 每天     |
| 灵活性预测   | 短期(24h)    | MAE < 15%  | 每小时   |

#### 6.1.2 基线计算算法

VPP结算依赖基线（Baseline）计算，要求：

- **数据窗口**：最近30天历史数据
- **计算方法**：滚动加权平均，近期数据权重更高
- **异常剔除**：自动识别并剔除异常日（节假日、故障日）
- **天气修正**：结合天气预报进行基线修正
- **输出频率**：每15分钟输出一个基线值

#### 6.1.3 预测接口规范

```json
{
  "method": "getForecast",
  "params": {
    "type": "PV_OUTPUT",
    "horizon": "SHORT_TERM",
    "period": "2026-05-10T00:00:00Z/2026-05-11T00:00:00Z",
    "resolution": 900,
    "location": {
      "latitude": 31.2304,
      "longitude": 121.4737
    }
  }
}
```

### 6.2 多时步前瞻优化引擎

#### 6.2.1 优化模型

采用混合整数线性规划（MILP）或启发式算法，在以下目标间权衡：

**优化目标（可配置权重）：**

1. 最小化用电成本
2. 最大化光伏消纳率
3. 最小化碳排放
4. 最大化设备寿命

#### 6.2.2 输入参数

| 参数     | 来源      | 描述                      |
| -------- | --------- | ------------------------- |
| 电价曲线 | 预测/市场 | 未来24小时分时电价        |
| 负荷预测 | 预测模型  | 未来24小时负荷曲线        |
| 光伏预测 | 预测模型  | 未来24小时光伏出力        |
| 设备约束 | 设备注册  | SOC限制、功率限制、爬坡率 |
| 物理约束 | 台区配置  | 变压器容量、线缆热容量    |

#### 6.2.3 输出结果

```json
{
  "schedule": [
    {
      "time": "2026-05-10T08:00:00Z",
      "ess_power": 50000,
      "ev_charge_limit": 7000,
      "pv_curtailment": 0
    },
    {
      "time": "2026-05-10T08:15:00Z",
      "ess_power": 30000,
      "ev_charge_limit": 5000,
      "pv_curtailment": 0
    }
  ],
  "expected_cost": 1250.5,
  "pv_self_consumption_rate": 0.92
}
```

### 6.3 曲线跟踪与轨迹控制

#### 6.3.1 轨迹跟踪控制器

EMS需具备P(t)功率目标轨迹的实时跟踪能力：

```
实际功率 ──── 目标曲线 ──── 偏差校正
    │           │           │
    ▼           ▼           ▼
  实时采样    计划值     PID控制器
    │           │           │
    └───────────┼───────────┘
                ▼
          斜率滤波器
                │
                ▼
          设备指令
```

#### 6.3.2 斜率滤波器规范

| 参数         | 默认值  | 范围     | 描述                   |
| ------------ | ------- | -------- | ---------------------- |
| 最大上升斜率 | 500 W/s | 100-2000 | 功率增加的最大速率     |
| 最大下降斜率 | 500 W/s | 100-2000 | 功率减少的最大速率     |
| 最小步长     | 100 W   | 50-500   | 单次调节的最小功率变化 |
| 调节周期     | 1 s     | 0.5-5    | 控制循环的执行周期     |

#### 6.3.3 多节点协调机制

为防止多个节点同步动作导致电网冲击，采用随机延迟（Jitter）机制：

```
节点A: 延迟 = hash(TA001) % 100ms = 23ms
节点B: 延迟 = hash(TA002) % 100ms = 67ms
节点C: 延迟 = hash(TA003) % 100ms = 45ms
```

### 6.4 交易回撤与灵活性再对账

#### 6.4.1 承诺状态机

```
                    ┌──────────┐
                    │  已成交   │
                    │ Committed│
                    └────┬─────┘
                         │
              ┌──────────┼──────────┐
              ▼          ▼          ▼
          ┌──────┐  ┌──────┐  ┌──────┐
          │执行中│  │撤回中│  │违约  │

          └──┬───┘  └──┬───┘  └──┬───┘
             │         │         │
             ▼         ▼         ▼
          ┌──────┐  ┌──────┐  ┌──────┐
          │已完成│  │已撤回│  │已上报│
          │Done  │  │Rolled│  │Report│
          └──────┘  └──────┘  └──────┘
```

#### 6.4.2 回撤响应流程

1. 接收交易撤回指令
2. 计算恢复成本（本地设备调整代价）
3. 通过头部识别码定位故障支路
4. 执行本地功率调整
5. 向云端上报违约容量和恢复成本
6. 更新信用评分

### 6.5 协同减载与带宽分配

#### 6.5.1 减载触发条件

| 触发源     | 触发条件            | 响应时间 |
| ---------- | ------------------- | -------- |
| 本地热约束 | 功率 > 额定容量×95% | <100ms   |
| 本地热约束 | I²t累积 > 阈值85%   | <500ms   |
| 电网广播   | 接收减载指令        | <50ms    |
| NILM异常   | 识别到故障指纹      | <200ms   |

#### 6.5.2 协调确认协议

```
节点A (过载)                   节点B (邻居)                  节点C (邻居)
    │                            │                            │
    ├── 减载请求 ───────────────►│                            │
    │                            ├── 转发请求 ───────────────►│
    │◄── 可承担30kW ────────────┤                            │
    │◄── 可承担20kW ────────────────────────────────────────┤
    │                            │                            │
    │  仲裁: B承担30kW, C承担20kW                            │
    │                            │                            │
    ├── 确认减载 ───────────────►│                            │
    │                            ├── 确认减载 ───────────────►│
    │◄── 执行完成 ──────────────┤◄── 执行完成 ──────────────┤
    │                            │                            │
```

#### 6.5.3 减载次序规范

| 批次  | 时间窗口        | 减载对象 | 动作               |
| ----- | --------------- | -------- | ------------------ |
| 第1批 | T+0~T+10ms      | L4级设备 | 立即切断           |
| 第2批 | T+10ms~T+100ms  | L3级设备 | 按斜率限流至50%    |
| 第3批 | T+100ms~T+500ms | L2级设备 | 按比例限流至70%    |
| 紧急  | 任意时刻        | 所有非L1 | 强制切断（需确认） |

#### 6.5.4 带宽分配算法

基于信用额度的动态配额管理：

```
可用带宽 = 变压器额定容量 × 季节系数 - 不可控负荷
各设备配额 = 可用带宽 × (设备信用分 / 总信用分)
```

## 7. 物理约束与安全模型

### 7.1 热容量与季节性带宽模型

#### 7.1.1 静态边界定义

| 参数     | 符号    | 单位 | 描述               |
| -------- | ------- | ---- | ------------------ |
| 额定功率 | P_rated | kW   | 变压器铭牌额定容量 |
| 额定电流 | I_rated | A    | 线缆长期允许载流量 |
| 环境温度 | T_amb   | °C   | 当前环境温度       |
| 温度系数 | K_temp  | -    | 温度修正系数       |

#### 7.1.2 动态热容量计算

```
P_max(T) = P_rated × K_temp(T_amb) × K_season

其中：
K_temp(T_amb) = 1 - 0.008 × (T_amb - 25)  (T_amb > 25°C)
K_temp(T_amb) = 1                          (T_amb ≤ 25°C)
K_season = 夏季: 0.9, 春秋: 1.0, 冬季: 1.1
```

#### 7.1.3 I²t热累积保护

```
I²t_integral = ∫I²(t)dt

预警阈值: I²t_integral > 85% × I²t_limit → 触发预收缩
动作阈值: I²t_integral > 95% × I²t_limit → 强制减载
恢复条件: I²t_integral < 60% × I²t_limit → 恢复正常调度
```

### 7.2 电压质量与谐波约束

#### 7.2.1 电压质量要求

| 参数     | 正常范围 | 告警阈值          | 动作阈值 |
| -------- | -------- | ----------------- | -------- |
| 电压偏差 | ±5% Un   | ±7% Un            | ±10% Un  |
| 电压跌落 | -        | <90% Un持续>20ms  | <80% Un  |
| 电压暂升 | -        | >110% Un持续>20ms | >120% Un |
| 频率偏差 | ±0.2Hz   | ±0.5Hz            | ±1.0Hz   |

#### 7.2.2 谐波约束

| 谐波次数 | 电压谐波限值 | 电流谐波限值 |
| -------- | ------------ | ------------ |
| THD      | <5%          | <8%          |
| 3次      | <3%          | <5%          |
| 5次      | <3%          | <5%          |
| 7次      | <2%          | <4%          |
| 9-15次   | <1.5%        | <3%          |

#### 7.2.3 虚拟阻抗调节

当电压偏差超过阈值时，EMS自动增加虚拟阻抗：

```
Z_virtual = Z_base × (1 + K_v × |ΔV| / V_ref)

其中：
Z_base = 基础阻抗
K_v = 电压调节系数（默认2.0）
ΔV = 电压偏差
V_ref = 额定电压
```

### 7.3 三相平衡管理

#### 7.3.1 不平衡度监测

```
不平衡度 = max(|Ia - Iavg|, |Ib - Iavg|, |Ic - Iavg|) / Iavg × 100%

正常: <15%
告警: 15%-25%
严重: >25%
```

#### 7.3.2 处理措施

| 不平衡度 | 处理措施                   |
| -------- | -------------------------- |
| <15%     | 正常监控，不干预           |
| 15%-25%  | 锁定过载相的新增负载接入   |
| >25%     | 触发负载迁移，生成运维报告 |

#### 7.3.3 负载迁移

对于支持相位切换的设备（高级充电桩），EMS可引导负载迁移至轻载相：

```
目标相位 = argmin(P_phase)  (选择当前负载最小的相位)
迁移条件: 目标相负载率 < 70% 且 迁移后不平衡度 < 15%
```

### 7.4 资产寿命与折旧跟踪

#### 7.4.1 跟踪指标

| 指标           | 单位 | 采集方式 |
| -------------- | ---- | -------- |
| 充放电循环次数 | 次   | 累计计数 |
| I²t累积        | A²s  | 实时积分 |
| 过载次数       | 次   | 事件计数 |
| 运行时间       | h    | 累计计时 |
| 最高温度       | °C   | 峰值记录 |

#### 7.4.2 折旧模型

```
剩余寿命 = 设计寿命 × (1 - Σ(工况损耗因子 × 运行时间比例))

工况损耗因子:
  额定工况: 1.0
  过载工况: 2.5
  高温工况: 1.8
  谐波工况: 1.3
```

#### 7.4.3 调度约束

当调度指令可能导致设备寿命极速衰减时，EMS有权：

1. **否决指令**：返回"指令被拒绝，原因：寿命损耗超标"
2. **协商替代**：提出替代方案，降低功率或延长时间
3. **要求补偿**：记录寿命损耗，要求更高的调度补偿
