# 附录A：自研聚合引擎说明

> **本文档是对《第一章：总体架构与设计理念》中"自研聚合引擎"的详细说明**
> **关联文档：** `01_总体架构与设计理念.md`（§2.3 GB/T 38755-2020 合规映射、§3.1 核心架构图、§3.4 双层ADMM优化架构）

---

## 1. 定位

"自研聚合引擎"是本 VPP 架构中**聚合层 - 资源聚合调度模块**的一个核心组件，与 **FlexMeasures**（开源聚合调度框架）配合使用，形成"开源底座 + 自研扩展"的组合方案。

---

## 2. 为什么需要自研聚合引擎？

文档中明确标注为：**FlexMeasures + 自研聚合引擎**，两者互补的原因如下：

| 维度         | FlexMeasures                       | 自研聚合引擎   |
| ------------ | ---------------------------------- | -------------- |
| **许可证**   | Apache 2.0（安全）                 | 自有知识产权   |
| **核心能力** | 通用资源调度优化（内置 Pyomo）     | 定制化业务逻辑 |
| **社区评价** | GitHub Stars 400+，社区活跃度 ⭐⭐ | -              |
| **国内支持** | ❌ 无                              | ✅ 完全可控    |

FlexMeasures 提供的是**通用化的多资源聚合调度框架**，但面对四川省的特定环境（见 §8 四川环境建模），存在多个无法由开源组件直接满足的需求：

1. **丰枯水期电价差异**（§8.1）：6-10月丰水期 vs 11-5月枯水期，电价模型需区分
2. **陇电入川联络线 ATC 建模**（§8.3）：跨省特高压联络线容量作为约束条件
3. **尖峰时段动态调整**（§8.2）：随天气/负荷动态变化的尖峰时段响应
4. **基本电费消减策略**（§8.4）：需量管理直接影响业主成本
5. **保供电预警与应急接管**（§8.5）：极端天气下的模式切换

---

## 3. 核心功能

### 3.1 虚拟节点聚合（与 §3.4 双层 ADMM 架构联动）

在 ADMM 双层优化架构中，自研聚合引擎负责将物理资产聚合为**虚拟大节点（Cluster）**：

| 聚合参数   | 计算逻辑                            |
| ---------- | ----------------------------------- |
| 总可调容量 | Σ(P_max_i - P_min_i)                |
| 总 SOC     | Σ(SOC_i × E_rated_i) / Σ(E_rated_i) |
| 总功率基线 | Σ(P_base_i)                         |
| 响应速率   | min(ramp_rate_i)                    |
| 调节精度   | max(precision_i)                    |

**聚合粒度演进**：

| 阶段             | 聚合粒度              | 虚拟节点数（全省） |
| ---------------- | --------------------- | :----------------: |
| Phase 1 单站     | 按设备类型聚合        |        ≤10         |
| Phase 2 区域聚合 | 按台区 + 资源类型     |       ≤1,000       |
| Phase 3 全省规模 | 按供电分区 + 资源类型 |      ≤10,000       |

### 3.2 四川电价元数据管理

- 维护多版本分时电价元数据（丰水期/枯水期/平水期）
- 季节性电价系数动态切换
- 尖峰时段自适应调整：
  - 夏季：11:00-12:00, 15:00-17:00（空调负荷高峰）
  - 冬季：10:00-12:00, 17:00-19:00（取暖负荷高峰）

### 3.3 需量管理（基本电费消减）

- 滚动 15 分钟需量监测与控制
- 储能充放电优化以消减最大需量
- 充电桩有序充电避免需量尖峰

### 3.4 保供模式切换

- 接收电网保供电预警信号
- 切换至"保供模式"：云端下发策略，边缘强制执行
- 联络线闭锁风险模拟
- 与有序用电方案联动

### 3.5 设备指纹管理（能源交换机范式，§4.1）

- 维护设备指纹库（类似"MAC地址表"）
- NILM 识别的设备特征指纹存储
- 物理身份校验

## 4. 应用场景

### 场景 1：家庭光伏+储能+充电桩聚合

```
家庭 A（光伏 5kW + 储能 10kWh + EV 7kW）
家庭 B（光伏 8kW + 储能 15kWh）
家庭 C（光伏 3kW + 空调 2kW）
  │
  ▼ 自研聚合引擎
  │  聚合为虚拟节点：总可调容量 = ±25kW，总 SOC = 65%
  │
  ▼ 上报上层（Pyomo 报价引擎）
  │  输出：该节点在 15:00-16:00 可放电 20kW
```

### 场景 2：台区变压器容量管理

```
台区变压器容量 630kVA
接入资源：光伏 300kW + 储能 200kW/400kWh + 充电桩 120kW + 居民负荷 250kW

自研聚合引擎：
  1. 实时监测变压器负载率
  2. 当负载率 > 95% 时，触发协同减载
  3. 按 L1-L4 分级标签（§4.1 QoS）分配带宽
  4. 优先保障 L1 关键负荷，削减 L3-L4 充电桩功率
```

### 场景 3：丰枯水期策略切换

```
6月1日（丰水期开始）：
  - 电价偏低，储能套利空间缩小
  - 自研聚合引擎自动切换电价模型
  - 调整储能充放电策略：减少峰谷套利，增加需量管理

11月1日（枯水期开始）：
  - 电价偏高，套利空间扩大
  - 切换电价模型，增加精细化报价
  - 优先保障储能可用容量参与交易
```

### 场景 4：保供电应急模式

```
四川高温红色预警（保供电触发）：
  1. 自研聚合引擎接收保供信号
  2. 切换至"保供模式"
  3. 停止所有市场化报价行为
  4. 储能转为"电网支撑"模式（放电）
  5. 充电桩限制功率（DLB 策略）
  6. 联络线闭锁：停止跨省售电
```

## 5. 与 FlexMeasures 的分工协作

```
┌─────────────────────────────────────────────────┐
│  自研聚合引擎                                     │
│  ┌──────────────────────┐  ┌──────────────────┐ │
│  │ 向上：交易层接口       │  │ 向下：FlexMeasures │ │
│  │ - 虚拟节点聚合参数上报 │  │ - 调度解析和拆分  │ │
│  │ - 四川电价元数据       │  │ - 需量管理执行   │ │
│  │ - 保供模式切换信号     │  │ - 物理约束回传   │ │
│  └──────────────────────┘  └──────────────────┘ │
└─────────────────────────────────────────────────┘
                        │
                        ▼
┌─────────────────────────────────────────────────┐
│  FlexMeasures (开源调度引擎)                      │
│  - 多资源类型建模（光伏/储能/充电桩/空调/热泵）   │
│  - 内置 Pyomo 调度求解器                         │
│  - 物理约束检查（三相平衡/变压器容量/SOC均衡）    │
│  - 本地控制闭环执行                              │
└─────────────────────────────────────────────────┘
```

## 6. 总结

**自研聚合引擎**不是重复造轮子，而是为了解决开源组件 FlexMeasures 无法覆盖的中国电力市场特有需求——尤其是四川省的丰枯水期电价模型、联络线 ATC 约束、需量管理策略和保供模式。它在架构中扮演"中间翻译层"的角色，向上对接交易层的经济优化，向下驱动 FlexMeasures 的物理调度，确保系统既能利用开源生态的成熟能力，又能满足中国电力市场的合规和定制化需求。
