## 1. 概述

STM32 微控制器在 VPP 三级响应架构中承担**第一级（硬件级响应，μs~ms）** 的核心角色。它通过 ADC 以 1kHz+ 采样电网电压/频率，检测到频率越限或电压跌落时，通过硬件 GPIO/PWM 直连 PCS，**不经过任何软件协议栈**，确保确定性延迟 <200ms。

本附录详细分析 STM32 的故障模式、可靠性保障措施，以及在不同部署场景下的冗余机制选型建议。

## 2. STM32 故障模式分析

### 2.1 故障模式与影响分析（FMEA）

| 故障模式                  | 故障概率                             | 检测方式                          | 对系统的影响                                  | 现有兜底机制                                                     | 风险等级 |
| ------------------------- | ------------------------------------ | --------------------------------- | --------------------------------------------- | ---------------------------------------------------------------- | -------- |
| **STM32 死机/看门狗复位** | 低（工业级 -40~85°C，MTBF ~50,000h） | 外部硬件看门狗超时                | 硬件级响应失效，响应时间从 <200μs 退化到 <5ms | 第二级 OpenEMS 通过 CAN/SPI 接管，响应时间仍在并网标准允许范围内 | 🟡 中    |
| **ADC 采样通道漂移/损坏** | 中低                                 | 第二级 EMS 交叉校验可发现异常数据 | 频率/电压检测偏差，可能误触发或漏触发         | 第二级二次校验 + 异常值检测，§12.1.3 故障注入已验证              | 🟡 中    |
| **GPIO/PWM 输出锁死**     | 极低                                 | 第二级检测 PCS 未收到预期信号     | PCS 收不到硬件级信号，依赖第二级 SPI/CAN 路径 | 第二级通过 CAN/SPI 仍可下发指令                                  | 🟢 低    |
| **固件异常/bug**          | 取决于开发质量                       | 单元测试 + SIL 测试 + HIL 测试    | 逻辑错误导致的误动作或不动作                  | 第二级 EMS 交叉校验可捕获大部分异常；固件 OTA 可修复             | 🟡 中    |
| **电源故障**              | 低                                   | 独立电源监控芯片检测              | STM32 完全失电                                | 需独立供电设计，无兜底                                           | 🔴 高    |
| **晶振失效**              | 极低                                 | 时钟检测电路                      | STM32 无法运行                                | 第二级 OpenEMS 接管                                              | 🟢 低    |
| **Flash 存储损坏**        | 极低                                 | CRC 校验失败                      | 固件加载失败                                  | 回退至备份固件区（双 Bank 启动）                                 | 🟢 低    |

### 2.2 核心结论

- **STM32 是单点，但没有它系统不会完全失效**——第二级（OpenEMS）仍可通过 CAN/SPI 路径在 ms 级响应
- **关键风险在于电网频率/电压跌落的黄金响应窗口是 100-500ms**，如果第一级失效仅靠第二级，可能超出 IEEE 1547-2018 并网标准要求的时间
- **电源故障是最严重的故障模式**，因为 STM32 和 OpenEMS 可能共享同一电源，电源失效会导致两级同时失效

## 3. 可靠性保障措施

### 3.1 硬件选型标准

| 配置项            | 最低要求                  | 推荐配置                         | 说明                                         |
| ----------------- | ------------------------- | -------------------------------- | -------------------------------------------- |
| **MCU 型号**      | STM32F4 系列（Cortex-M4） | STM32H7 系列（Cortex-M7）        | H7 系列带 ECC RAM，双精度 FPU，双 Bank Flash |
| **温度范围**      | 工业级 -40~85°C           | 扩展工业级 -40~105°C             | 户外机柜夏季内部温度可达 70°C+               |
| **ECC RAM**       | ❌ 不支持                 | ✅ 支持（STM32H7 内置）          | 防止 SEU（单粒子翻转）导致的随机故障         |
| **双 Bank Flash** | ❌ 不支持                 | ✅ 支持                          | 支持安全固件 OTA，回滚保护                   |
| **外部看门狗**    | ✅ 必须                   | 独立硬件看门狗芯片（如 MAX6369） | 内部看门狗在 MCU 时钟故障时可能失效          |
| **独立电源监控**  | ❌ 可选                   | ✅ 必须（如 TPS3702）            | 检测电源跌落，提前触发安全状态               |
| **ADC 参考电压**  | 内部参考                  | 外部精密参考（如 REF5030）       | 提高采样精度，减少温漂                       |

### 3.2 独立供电设计

> **⚠️ 关键安全设计**：电源故障是最严重的故障模式，因为 STM32 和 OpenEMS 可能共享同一电源。必须确保 STM32 的供电独立于 OpenEMS 主系统。

```
┌──────────────────────────────────────────────────────────────────────────┐
│  边缘网关电源架构                                                         │
│                                                                          │
│  外部 DC 电源（48V / 24V）                                                │
│         │                                                                │
│         ├──→ DC/DC 1（48V→12V）──→ OpenEMS 主系统（树莓派 / x86）         │
│         │         │                                                      │
│         │         └──→ 独立 LDO（12V→3.3V）──→ STM32（独立供电轨）        │
│         │                                                                │
│         └──→ DC/DC 2（48V→5V）──→ 外部硬件看门狗 + 电源监控芯片           │
│                                                                          │
│  备用电源：超级电容（5F/5.5V）──→ STM32（保持 500ms 完成安全关断）        │
└──────────────────────────────────────────────────────────────────────────┘
```

**设计要点**：

| 要求           | 说明                                                                  |
| -------------- | --------------------------------------------------------------------- |
| **独立供电轨** | STM32 使用独立的 LDO 供电，不与 OpenEMS 主系统共享 3.3V 电源轨        |
| **电源监控**   | 独立电源监控芯片（如 TPS3702）监控 STM32 供电电压，低于阈值时触发中断 |
| **备用电源**   | 超级电容提供 500ms 保持时间，确保 STM32 在电源跌落时完成安全关断序列  |
| **上电时序**   | STM32 先于 OpenEMS 上电，确保 PCS 在 EMS 启动前已处于安全状态         |

### 3.3 固件可靠性

| 措施             | 实现方式                                      | 说明                            |
| ---------------- | --------------------------------------------- | ------------------------------- |
| **双 Bank 启动** | STM32H7 双 Bank Flash，Bank0 运行，Bank1 备份 | OTA 失败时自动回退至 Bank1      |
| **CRC 校验**     | 固件加载时 CRC32 校验，启动失败自动回退       | 防止 Flash 损坏导致的启动失败   |
| **看门狗喂狗**   | 主循环中喂狗，死循环/卡死时自动复位           | 外部硬件看门狗，独立于 MCU 时钟 |
| **安全 OTA**     | 签名固件（SM2 签名），验签通过后才写入        | 防止恶意固件注入                |
| **版本回滚**     | 保留最近 3 个固件版本，支持远程回滚           | OTA 异常时可快速恢复            |

### 3.4 软件可靠性

| 措施               | 实现方式                                                    |
| ------------------ | ----------------------------------------------------------- |
| **状态机设计**     | 明确的 INIT → RUN → FAULT → RECOVERY 状态转换，无未定义状态 |
| **看门狗喂狗策略** | 仅在主循环完成一次完整采样→检测→输出周期后喂狗              |
| **异常值检测**     | ADC 采样值超出物理范围（如电压 > 300V）时丢弃并计数         |
| **故障计数**       | 连续 N 次异常采样后触发 FAULT 状态，而非单次触发            |
| **SOE 记录**       | 所有状态转换和故障事件记录到内部 Flash，供事后分析          |

## 4. 冗余机制方案对比

### 4.1 方案 A：单 STM32 + 外部硬件看门狗（当前方案）

```
┌──────────────┐    GPIO/PWM    ┌──────────────┐
│  单 STM32     │──────────────→│  PCS          │
│  + 外部看门狗  │               │               │
│  + 电源监控    │  CAN/SPI     │               │
│              │──────────────→│  (备用路径)    │
└──────────────┘               └──────────────┘
```

| 维度           | 评估                                               |
| -------------- | -------------------------------------------------- |
| **MTBF**       | ~50,000 小时（~5.7 年）                            |
| **年失效率**   | ~2%/年                                             |
| **硬件成本**   | ¥0（基线方案）                                     |
| **开发复杂度** | 🟢 低                                              |
| **失效影响**   | 硬件级降级为 EMS 级，响应时间从 <200μs 退化到 <5ms |
| **适用场景**   | 非保供场景、日常削峰填谷、成本敏感型部署           |

### 4.2 方案 B：双 STM32 热备（2选1）

```
┌──────────────┐
│  STM32 #1    │───┐    ┌──────────────┐
│  (主)        │   ├───→│  或门/GPO    │──→ PCS
│              │   │    └──────────────┘
├──────────────┤   │
│  STM32 #2    │───┘
│  (备)        │ 心跳互检
│              │────────→ OpenEMS（仲裁）
└──────────────┘
```

**工作机制**：

| 步骤 | 描述                                                       |
| ---- | ---------------------------------------------------------- |
| 1    | 主 STM32 正常工作时，备 STM32 处于同步就绪状态             |
| 2    | 主 STM32 通过心跳信号（独立 GPIO，1Hz 方波）告知备机状态   |
| 3    | 备 STM32 检测到主机心跳丢失超过 100ms 时接管 GPIO/PWM 输出 |
| 4    | 输出端使用**或门逻辑**（任一 STM32 触发保护信号即生效）    |
| 5    | OpenEMS 通过 CAN/SPI 同时与两片 STM32 通信，监控双方状态   |
| 6    | 主备切换后，OpenEMS 记录切换事件并触发告警                 |

| 维度               | 评估                                              |
| ------------------ | ------------------------------------------------- |
| **MTBF**           | ~2.5×10⁹ 小时（双机热备理论值）                   |
| **年失效率**       | <0.01%/年                                         |
| **硬件成本增加**   | ~¥30-50（多一片 STM32 + 或门逻辑）                |
| **开发复杂度增加** | 🟡 中（需实现心跳同步 + 仲裁逻辑 + 输出冲突避免） |
| **失效影响**       | 单 STM32 故障不影响系统功能，无降级               |
| **适用场景**       | 保供电站点、工商业储能、充电站 V2G                |

### 4.3 方案 C：三 STM32 表决（3选2）

```
┌──────────────┐  频率检测  ┌──────────────┐
│  STM32 #1    │───────────→│               │
├──────────────┤  频率检测   │  3选2 表决器   │──→ PCS
│  STM32 #2    │───────────→│  (硬件逻辑)    │
├──────────────┤  频率检测   │               │
│  STM32 #3    │───────────→│               │
└──────────────┘            └──────────────┘
```

**工作机制**：

| 步骤 | 描述                                                               |
| ---- | ------------------------------------------------------------------ |
| 1    | 三片 STM32 独立采样、独立检测频率/电压                             |
| 2    | 3选2 表决器（硬件逻辑，非软件）判断多数是否触发                    |
| 3    | 任意 2 片触发保护信号即输出到 PCS                                  |
| 4    | 可容忍单 STM32 故障（任一故障不影响系统，也不误动）                |
| 5    | 故障定位：OpenEMS 通过 CAN/SPI 读取三片 STM32 的状态，定位故障节点 |

| 维度               | 评估                                                   |
| ------------------ | ------------------------------------------------------ |
| **MTBF**           | 极高（3 取 2 可容忍任意 1 片故障）                     |
| **年失效率**       | <0.001%/年                                             |
| **硬件成本增加**   | ~¥60-100（多两片 STM32 + 3选2 表决逻辑芯片）           |
| **开发复杂度增加** | 🔴 高（三路 ADC 校准、一致性同步、表决逻辑、故障定位） |
| **失效影响**       | 单 STM32 故障不影响系统，无降级                        |
| **适用场景**       | 极少需要，仅在极高可靠性要求的场景                     |

### 4.4 方案对比总结

| 维度             | 方案 A：单 STM32 | 方案 B：双 STM32 热备 | 方案 C：三 STM32 表决 |
| ---------------- | ---------------- | --------------------- | --------------------- |
| **年失效率**     | ~2%/年           | <0.01%/年             | <0.001%/年            |
| **硬件成本增量** | ¥0（基线）       | +¥30-50               | +¥60-100              |
| **开发复杂度**   | 🟢 低            | 🟡 中                 | 🔴 高                 |
| **失效影响**     | 降级至 EMS 级    | 无影响                | 无影响                |
| **适用场景**     | 居民侧 HEMS      | 保供/工商业/充电站    | 极少需要              |

## 5. 推荐方案：分级冗余策略

### 5.1 分级策略

鉴于不同部署场景对可靠性的要求不同，建议**不采用一刀切方案，而是分级处理**：

| 部署场景                           | 推荐方案                          | 理由                                                                    |
| ---------------------------------- | --------------------------------- | ----------------------------------------------------------------------- |
| **保供电站点**（红色预警覆盖区域） | **方案 B：双 STM32 热备（2选1）** | 成本可控（+¥30-50），失效率降至 <0.01%/年，满足保供场景的极高可靠性要求 |
| **工商业储能站点**                 | **方案 A：单 STM32 + 外部看门狗** | 现有方案已足够，第二级 EMS 可兜底                                       |
| **居民侧 HEMS**                    | **方案 A：单 STM32 + 内部看门狗** | 成本敏感，且居民侧对响应时间要求较低                                    |
| **充电站 V2G**                     | **方案 A：单 STM32 + 外部看门狗** | 同工商业站点                                                            |

### 5.2 为什么 3选2 不是推荐方案

在电力系统的**保护装置**中确实常用 3选2（如继电保护），但在 VPP 场景中：

1. **VPP 的 STM32 是辅助保护而非主保护**——电网本身有变电站级的保护装置（继电保护、低频减载），VPP 的 STM32 是 VPP 内部资产的自我保护，不是并网的主保护
2. **失效后果可控**——STM32 失效时第二级（EMS）可在 5ms 内响应，仍在 IEEE 1547-2018 的并网标准要求范围内
3. **3选2 的边际收益递减**——从 2选1 到 3选2，可靠性的提升很小（从 0.01%/年到 0.001%/年），但成本和复杂度增加显著（需要三路 ADC 校准、同步、表决）

### 5.3 双 STM32 热备实施要点

如果选择方案 B（双 STM32 热备），以下为关键实施要点：

#### 5.3.1 硬件设计

| 项目         | 要求                                                     |
| ------------ | -------------------------------------------------------- |
| **PCB 布局** | 两片 STM32 独立供电轨、独立晶振、独立 ADC 采样通道       |
| **心跳信号** | 独立 GPIO，1Hz 方波，主→备单向                           |
| **输出或门** | 使用 74LVC1G32 或门芯片，任一 STM32 触发即输出           |
| **隔离**     | 两片 STM32 的 GPIO/PWM 输出端加 100Ω 限流电阻，防止短路  |
| **CAN 总线** | 两片 STM32 共用 CAN 总线与 OpenEMS 通信，使用不同 CAN ID |

#### 5.3.2 软件设计

| 项目         | 要求                                                             |
| ------------ | ---------------------------------------------------------------- |
| **心跳超时** | 备 STM32 检测到心跳丢失 >100ms 即接管输出                        |
| **同步机制** | 主 STM32 通过 CAN 广播当前状态（频率、电压、触发阈值），备机同步 |
| **防抖动**   | 心跳丢失后等待 3 个周期（3s）才确认主 STM32 故障，防止误切换     |
| **恢复机制** | 主 STM32 恢复后，备 STM32 自动让出输出控制权（需 OpenEMS 确认）  |
| **故障记录** | 切换事件记录到 OpenEMS 的 SOE 日志                               |

#### 5.3.3 测试验证

| 测试场景          | 验证方法             | 验收标准                      |
| ----------------- | -------------------- | ----------------------------- |
| 主 STM32 死机     | 切断主 STM32 供电    | 备 STM32 在 100ms 内接管输出  |
| 主 STM32 恢复     | 恢复主 STM32 供电    | 主 STM32 在 3s 内重新接管输出 |
| 双 STM32 同时触发 | 注入 50.5Hz 频率信号 | 或门输出一次，无冲突          |
| 备 STM32 故障     | 切断备 STM32 供电    | 主 STM32 正常运行，无影响     |
