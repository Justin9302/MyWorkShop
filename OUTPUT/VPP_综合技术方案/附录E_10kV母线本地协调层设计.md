# 附录E：10kV母线本地协调层设计（已废弃）

> **⚠️ 本附录已废弃**。经商业可行性评估，该方案在中国电网环境下缺乏应用场景。联网状态下的跨台区带宽共享能力已通过聚合层（FlexMeasures）的ADMM架构实现（纯软件方案），详见01\_总体架构与设计理念.md §4.3 带宽分配模型。

---

## E.1 背景与动机

### E.1.1 问题描述

在当前架构中，台区之间的所有协同均通过聚合层（云端）完成：

```
台区A (OpenEMS) ──MQTT──→ 聚合层 (FlexMeasures) ←──MQTT── 台区B (OpenEMS)
```

这种架构在**并网正常运行**时没有问题。但在**离网孤岛**状态下（如上级电网故障、计划孤岛测试、保供电场景），各台区失去与云端的连接，只能各自按预置策略独立运行，无法在10kV母线层面做任何协同响应：

| 模式         | 台区A          | 台区B          | 台区C          | 10kV母线级协同    |
| ------------ | -------------- | -------------- | -------------- | ----------------- |
| 并网正常     | 云端调度       | 云端调度       | 云端调度       | ✅ 通过聚合层实现 |
| **离网孤岛** | 按预置策略运行 | 按预置策略运行 | 按预置策略运行 | ❌ **无协同**     |

### E.1.2 离网无协同的风险

| 风险              | 现象                                         | 后果                     |
| ----------------- | -------------------------------------------- | ------------------------ |
| **功率倒送**      | A台区光伏满发，B台区负荷很低                 | 10kV母线过压，逆变器脱网 |
| **缺电**          | C台区负荷大、储能放空，A台区储能满电但不支援 | 孤岛自持时间缩短         |
| **频率/电压失稳** | 各台区独立调节，互相抵消                     | 孤岛系统崩溃             |
| **黑启动失败**    | 无法协调多台区有序恢复                       | 黑启动方案不可行         |

### E.1.3 适用场景

| 场景                    | 是否需要10kV本地协调 | 说明                   |
| ----------------------- | -------------------- | ---------------------- |
| 纯并网经济优化          | ❌ 不需要            | 云端聚合层已满足需求   |
| 保供电（红色/橙色预警） | ✅ 推荐              | 离网孤岛时需多台区协同 |
| 黑启动                  | ✅ 推荐              | 需要有序恢复多台区     |
| 计划孤岛测试            | ✅ 推荐              | 需通过电网孤岛运行验收 |
| 需量管理（离线）        | ⚠️ 可选              | 单台区独立响应也可接受 |

## E.2 设计目标

| 目标           | 要求                                                                   |
| -------------- | ---------------------------------------------------------------------- |
| **离线自治**   | 云端断连时，10kV母线级协同不依赖云端                                   |
| **实时性**     | 台区间信息交换延迟 <1ms                                                |
| **安全性**     | 不增加TCP/IP攻击面，符合I区安全隔离要求                                |
| **数据最小化** | 只交换聚合态数据（P_total、Q_total、孤岛状态），不交换设备级细粒度数据 |
| **与云端兼容** | 云端在线时以云端调度指令为准，云端离线时本地仲裁接管                   |
| **降级兜底**   | 本地协调层失效时，各台区回退到独立预置策略                             |

### E.3.2 物理隔离设计

每个台区OpenEMS工控机配置两个物理隔离的以太网口：

```
OpenEMS 工控机
┌─────────────────────────────────────┐
│                                     │
│  eth0: MQTT/TLS → 云端 (II/III区)   │ ← 与现有架构一致
│       (分配IP地址，连接MQTT网络)     │
│                                     │
│  eth1: GOOSE 组播 → 10kV母线局域网   │ ← 新增，隔离网络
│       (不分配IP地址，仅L2链路层)     │
│       (连接独立的10kV母线交换机)      │
└─────────────────────────────────────┘

安全隔离措施：
• eth0 和 eth1 位于两个不同的物理网络
• eth1 不分配IP地址（只有MAC地址，无TCP/IP协议栈）
• eth1 接在独立的VLAN中，与云端网络物理隔离
• 交换机端口安全：MAC白名单，只允许已注册的GOOSE Publisher
```

### E.3.3 通讯介质选型

| 场景                   | 推荐介质              | 最大距离 | 说明               |
| ---------------------- | --------------------- | -------- | ------------------ |
| 同一配电房内（<100m）  | 超五类/六类屏蔽双绞线 | 100m     | 成本最低           |
| 园区内分布（100m-2km） | 多模光纤              | 2km      | 抗电磁干扰         |
| 跨街区分布（2km-40km） | 单模光纤              | 40km     | 长距离             |
| 高电磁干扰环境         | 光纤（首选）          | 不限     | 配电房电磁环境复杂 |

> **建议**：即使短距离也优先使用光纤，配电房内PCS逆变器产生的电磁干扰可能影响屏蔽双绞线的信号质量。

## E.5 GOOSE协议设计

### E.5.1 数据模型

每个台区通过GOOSE组播发布以下数据：

| 数据对象          | 类型    | 长度         | 说明                                                   |
| ----------------- | ------- | ------------ | ------------------------------------------------------ |
| **P_total**       | FLOAT32 | 4字节        | 台区总有功功率（kW），正值=从电网取电，负值=向电网送电 |
| **Q_total**       | FLOAT32 | 4字节        | 台区总无功功率（kVar）                                 |
| **Island_Status** | BOOLEAN | 1字节        | 孤岛检测状态：0=并网，1=孤岛                           |
| **SOC_avg**       | FLOAT32 | 4字节        | 台区储能平均SOC（%）                                   |
| **SOC_min**       | FLOAT32 | 4字节        | 台区储能最低SOC（%）                                   |
| **Timestamp**     | UINT32  | 4字节        | 时间戳（Unix秒）                                       |
| **Reserved**      | -       | 29字节       | 预留扩展字段                                           |
| **总计**          |         | **约50字节** |                                                        |

### E.5.2 报文格式

GOOSE报文遵循IEC 61850-8-1标准：

```
以太网帧头（14字节）：
  Destination MAC: 01-0C-CD-01-00-01 (GOOSE组播MAC)
  Source MAC:      XX-XX-XX-XX-XX-XX (台区OpenEMS MAC)
  VLAN Tag:        0x8100 + VLAN ID (可选)

GOOSE头部（36字节）：
  APPID:           0x0001-0xFFFF (台区标识)
  Length:          报文总长度
  Reserved1/2:     0x0000
  gocbRef:         GOOSE控制块引用
  timeAllowedtoLive: 存活时间
  datSet:          数据集引用
  goID:            GOOSE标识
  t:               时间戳
  stNum:           状态序列号
  sqNum:           序列号
  simulation:      仿真标志
  ndsCom:          是否需要确认
  numDatSetEntries: 数据集条目数

数据载荷（约50字节）：
  P_total, Q_total, Island_Status, SOC_avg, SOC_min, Timestamp
```

### E.5.3 发送频率

| 状态         | 发送频率               | 说明                               |
| ------------ | ---------------------- | ---------------------------------- |
| **稳态**     | 5帧/秒                 | 无事件变化时周期性发送             |
| **事件触发** | 立即发送，1ms内重发3次 | 检测到孤岛、功率突变等事件时       |
| **事件后**   | 逐渐降回5帧/秒         | 事件后以20帧/秒→10帧/秒→5帧/秒递减 |

### E.5.4 带宽占用

```
稳态：50字节 × 5帧/秒 × 4台区 = 1,000 bytes/s = 8 kbps
事件：50字节 × 3帧 × 4台区 = 600 bytes（瞬时突发）
```

在100Mbps交换机上，这个带宽几乎可以忽略不计。

## E.6 仲裁逻辑

### E.6.1 10kV协调仲裁节点职责

| 职责               | 说明                                             |
| ------------------ | ------------------------------------------------ |
| **订阅GOOSE数据**  | 接收所有台区发布的P_total、Q_total、孤岛状态     |
| **孤岛检测确认**   | 综合各台区孤岛状态，确认10kV母线是否处于孤岛模式 |
| **功率平衡计算**   | 计算10kV母线总功率偏差：ΔP = ΣP_total（目标=0）  |
| **协同调度决策**   | 当ΔP超过阈值时，向各台区发布协同调度指令         |
| **与云端指令协调** | 云端在线时以云端指令为准，云端离线时本地仲裁接管 |

### E.6.2 仲裁决策流程

```
┌─────────────────────────────────────────────────────────────────────┐
│  10kV协调仲裁节点决策流程                                            │
│                                                                     │
│  步骤1：订阅各台区GOOSE数据                                          │
│    ├── 台区A: P_total=-50kW, SOC_avg=80%, Island_Status=1           │
│    ├── 台区B: P_total=+80kW, SOC_avg=45%, Island_Status=1           │
│    └── 台区C: P_total=+30kW, SOC_avg=60%, Island_Status=1           │
│                                                                     │
│  步骤2：孤岛确认                                                    │
│    └── 所有台区Island_Status=1 → 10kV母线处于孤岛模式                │
│                                                                     │
│  步骤3：功率平衡计算                                                │
│    └── ΔP = (-50) + 80 + 30 = 60kW（缺电60kW）                      │
│                                                                     │
│  步骤4：协同调度决策                                                │
│    ├── 台区A：SOC最高(80%)，可放电 → 增加放电功率至-100kW           │
│    ├── 台区B：SOC最低(45%)，需保供 → 减少负荷至+50kW               │
│    └── 台区C：SOC中等(60%)，维持现状 → 保持+30kW                   │
│                                                                     │
│  步骤5：发布GOOSE协同指令                                            │
│    └── 各台区收到指令后调整本地控制策略                              │
│                                                                     │
│  步骤6：持续监控（循环回到步骤1）                                    │
│    └── 每100ms重新计算，直到ΔP < 5kW                                │
└─────────────────────────────────────────────────────────────────────┘
```

### E.6.3 与云端调度指令的优先级

| 状态                | 调度决策来源               | 说明                                 |
| ------------------- | -------------------------- | ------------------------------------ |
| **并网 + 云端在线** | 云端聚合层（FlexMeasures） | 10kV仲裁节点仅监控，不干预           |
| **并网 + 云端离线** | 各台区独立预置策略         | 10kV仲裁节点不干预（并网时电网支撑） |
| **离网 + 云端在线** | 云端聚合层（通过MQTT）     | 10kV仲裁节点辅助执行云端指令         |
| **离网 + 云端离线** | **10kV仲裁节点接管**       | 本地协同调度，直到云端恢复           |

### E.6.4 降级兜底

| 故障场景              | 降级行为                           | 恢复条件               |
| --------------------- | ---------------------------------- | ---------------------- |
| 10kV仲裁节点失效      | 各台区回退到独立预置策略           | 仲裁节点恢复后自动接管 |
| GOOSE交换机故障       | 各台区回退到独立预置策略           | 交换机恢复后自动恢复   |
| 单个台区GOOSE通信中断 | 其他台区继续协同，中断台区独立运行 | 通信恢复后自动加入     |
| 所有台区GOOSE通信中断 | 各台区独立运行                     | 网络恢复后自动恢复     |

## E.7 安全约束

### E.7.1 安全设计原则

| 原则           | 措施                                                             |
| -------------- | ---------------------------------------------------------------- |
| **无IP地址**   | GOOSE通信使用以太网链路层（L2），不分配IP地址，无TCP/IP协议栈    |
| **物理隔离**   | 10kV母线GOOSE网络与MQTT云端网络使用独立的物理网口和交换机        |
| **VLAN隔离**   | GOOSE网络使用独立VLAN，与其它网络流量隔离                        |
| **MAC白名单**  | 交换机端口安全：只允许已注册的GOOSE Publisher MAC地址            |
| **数据最小化** | 只交换聚合态数据（P_total、Q_total、孤岛状态），不交换设备级数据 |
| **无路由**     | GOOSE组播限制在同一广播域，不跨路由器                            |

### E.7.2 与等保2.0三级合规的关系

| 等保要求       | 本方案满足情况                              |
| -------------- | ------------------------------------------- |
| I区物理隔离    | ✅ GOOSE网络在I区内独立运行，不连接II/III区 |
| 无TCP/IP攻击面 | ✅ GOOSE使用L2链路层，无IP地址              |
| 最小化暴露     | ✅ 只交换聚合态数据，不交换设备级数据       |
| 审计日志       | ✅ 仲裁节点记录所有GOOSE事件日志            |
| 故障隔离       | ✅ 单台区GOOSE故障不影响其他台区            |

### E.7.3 与附录C安全加固方案的关系

本附录的10kV本地协调层与附录C[^附录C]的安全加固方案**不冲突**：

- 附录C处理的是**DMZ区→II区**的DR信号接收安全
- 本附录处理的是**I区内**的10kV母线台区间通信
- 两者位于不同的安全域，互不影响

### E.8.3 与ADMM双层优化架构的关系

本附录的10kV本地协调层与ADMM架构（§3.4）的关系：

```
ADMM架构（云端在线时）：
  交易层（Pyomo）→ 聚合层（FlexMeasures）→ 边层（OpenEMS）
                                              ↑
  10kV本地协调层：仅监控，不干预 ──────────────┘

ADMM架构（云端离线+离网时）：
  10kV本地协调层（仲裁节点）→ 边层（OpenEMS）
  （替代聚合层的下层求解功能，但仅做功率平衡，不做经济优化）
```
