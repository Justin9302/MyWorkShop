# 分阶段实施方案头脑风暴

> 基于《平台方案商业技术可行性分析报告》的详细实施路线图
> 头脑风暴日期：2026-05-07
> 说明：HEMS 作为可选扩展，在中期阶段按需启动

---

## 一、总体原则

1. **先验证，后投入** — 每个阶段必须有明确的"Go/No-Go"决策点
2. **最小闭环优先** — 不要 All-in 全家桶，先跑通一个完整商业闭环
3. **数据飞轮 > 功能堆砌** — 每个阶段都要产生可复用的数据资产
4. **技术栈做减法** — Python + Go 为主，Java/C++ 按需引入
5. **HEMS 作为选项** — 不强制捆绑，根据 B 端进展和市场信号决定是否启动

## 三、Phase 0：市场验证与原型搭建（1-2个月）

### 3.1 目标

- 验证"头寸管理"价值主张是否被目标客户认可
- 搭建最小技术原型，跑通"电价获取 → 策略计算 → 收益模拟"链路
- 锁定1-2个意向合作站点，签署意向书（LOI）

### 3.2 关键任务

#### 3.2.1 市场验证（第1-3周）

| 任务                                             | 产出                  | 负责人建议     |
| ------------------------------------------------ | --------------------- | -------------- |
| 访谈5-10家四川工商业储能业主/聚合商              | 客户需求验证报告      | 电力分析师     |
| 分析四川电力现货市场规则（丰枯水期、联络线约束） | 市场规则白皮书        | 电力分析师     |
| 调研竞品（国网系、大厂、创业公司）定价和功能     | 竞品分析矩阵          | Python工程师兼 |
| 确定目标客户画像和首批意向站点                   | 目标客户清单（含LOI） | 团队共同       |

**关键问题清单（访谈用）：**

1. 当前储能/光伏资产的实际收益率是多少？
2. 最痛的点是什么？（电价波动风险？手动调度？结算对账？）
3. 如果有一个工具能自动优化充放电策略并控制风险，愿意付多少钱？
4. 对"收益分成"vs"固定SaaS订阅"的偏好？
5. 是否愿意开放设备数据接口？

#### 4.2.3 核心业务模块开发（第3-6个月）

**模块一：数据管道**

- 实时采集（秒级）：PCS功率、SOC、电表读数
- 准实时采集（分钟级）：电价、天气
- 数据清洗：异常值检测、缺失值填充、时间对齐
- 数据存储：TDengine 时序写入 + PostgreSQL 财务写入

**模块二：策略引擎**

- 日前策略：基于次日电价预测，优化充放电计划
- 日内调整：基于实时电价偏差，15分钟滚动优化
- 风险控制：CVaR约束、最大回撤限制、联络线偏差预警

**模块三：结算对账**

- 收益计算：峰谷套利、需量管理、需求响应
- 偏差考核：实际 vs 计划偏差量计算
- 分成结算：按合同模板自动生成结算单

**模块四：监控告警**

- 设备状态：离线、故障、异常数据
- 策略执行：实际 vs 计划偏差超阈值
- 市场风险：电价剧烈波动、政策变化预警

## 十二、总结

### 12.1 核心结论

1. **分阶段、有节奏** — 4个阶段，3个Go/No-Go决策点，每个阶段都有明确的退出机制
2. **先B后C** — 先验证B端商业闭环，再考虑C端HEMS扩展
3. **技术做减法** — Python + Go 为主，避免 Java/C++ 的复杂度
4. **数据是核心资产** — 每个阶段都要积累可复用的数据，形成数据飞轮
5. **HEMS 是选项，不是必须** — 根据市场信号和业务进展决定是否启动

### 12.3 成功的关键因素

2. **Phase 1 的站点运营** — 3-5个站点的稳定运营是证明商业模式的关键
3. **Phase 2 的产品化** — 从"项目"到"产品"的转变决定了规模化能力
4. **Phase 3 的生态融合** — B+C端融合是最终的价值释放
