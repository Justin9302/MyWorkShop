## 一、已达成共识

### 1.1 核心原则

| #   | 原则                 | 说明                                                                   |
| --- | -------------------- | ---------------------------------------------------------------------- |
| 1   | **框架一致性**       | 从 Phase 0 到 Phase 3，架构框架不推翻重做，采用"骨架→长肉"的渐进式演进 |
| 2   | **Phase 0 要出效果** | 第一阶段要让团队看到希望、提振士气，同时能对外客户演示                 |
| 3   | **先B后C**           | 先验证B端商业闭环，HEMS作为可选扩展后续讨论                            |
| 4   | **技术栈做减法**     | Python + Go 为主，避免过度复杂                                         |

### 1.2 Local EMS 定位

| 项目         | 结论                                                                        |
| ------------ | --------------------------------------------------------------------------- |
| **最终目标** | 完整的本地EMS（目标2）：具备独立调度能力，云端离线也能自主运行              |
| **实现路径** | 轻量边缘代理（Phase 0-1）→ 增强型边缘EMS（Phase 2）→ 完整本地EMS（Phase 3） |
| **技术选型** | 参考 OpenEMS 的协议知识，但用 Go 重写轻量代理（非直接跑 OpenEMS Java 版）   |

### 1.3 硬件平台

| 项目     | 规格                                     |
| -------- | ---------------------------------------- |
| CPU      | Cortex A53 四核                          |
| 内存     | 1GB                                      |
| OS       | Ubuntu 20.04 最小内核                    |
| 网络     | WiFi + 双网卡                            |
| 接口     | 4路RS485 + 1路CAN                        |
| 存储     | SD卡 + 8GB Flash                         |
| **结论** | Phase 0-1 完全够用，Phase 2 可能需要升级 |

### 1.4 Go vs Java 在边缘设备的资源对比

| 维度     |    Go    | Java (OpenJDK 11+) |      差距       |
| -------- | :------: | :----------------: | :-------------: |
| 空载内存 | 5-10 MB  |     80-150 MB      | Go 低 10-20 倍  |
| 完整应用 | 30-60 MB |     300-500 MB     |  Go 低 6-10 倍  |
| 启动时间 |  <100ms  |       3-10秒       | Go 快 30-100 倍 |
| 交叉编译 | 原生支持 |    需要 ARM JDK    |    Go 更方便    |

**结论：在 1GB 设备上，Go 比 Java 有显著优势，建议边缘代理用 Go 开发。**

### 1.5 evcc.io 评估

| 项目             | 结论                                                                              |
| ---------------- | --------------------------------------------------------------------------------- |
| 是否适合工业用途 | ❌ 不适合                                                                         |
| 原因             | 定位家庭用户，缺乏工业协议（DL/T 645、IEC 104），无多设备协同调度，边缘自治能力弱 |

### 2.2 Phase 0 目标（C级：内部跑通+外部演示）

- ✅ 可演示的收益模拟器（给客户看）
- ✅ 1个真实站点数据接入（证明能落地）
- ✅ 至少1份LOI（客户意向）
- ✅ 团队士气↑（看到完整链路跑通）

### 2.3 Phase 0 团队配置（3-4人）

| 角色                 | 人数 | 负责                                 |
| -------------------- | :--: | ------------------------------------ |
| Python 算法工程师    |  1   | 电价预测、优化模型、策略引擎         |
| Go/Python 后端工程师 |  1   | API、数据管道、Streamlit 展示        |
| IoT/嵌入式工程师     | 1-2  | 边缘代理 Go 开发、协议适配、现场部署 |
