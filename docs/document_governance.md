# Document Governance — 工作文档版本治理规范

> 版本: 1.0.0 | 状态: published | 最后修改: 2026-05-26

---

## 1. 概述

本文档定义 `OUTPUT/` 目录下**工作文档（业务文档、技术方案、研究报告等）** 的版本治理规范。所有工作文档的创建、修改、版本晋升和废弃均应遵循本规范。

### 核心原则

1. **可追溯** — 每份文档的版本历史清晰可查，变更原因有记录
2. **可回溯** — 任何版本均可通过 Git 提交历史恢复
3. **一致性** — 所有文档采用统一的编号、版本号和元数据格式
4. **可集成** — 文档版本可纳入平台 Release 治理体系

### 适用范围

本规范适用于 `OUTPUT/` 目录下所有非平台资产的工作文档，包括但不限于：

- 技术方案文档（如 VPP 综合技术方案系列）
- 研究报告（如 country_report、投资评估报告）
- 标准规范草案
- 头脑风暴记录
- 项目分析报告

## 2. 文档编号规范

### 2.1 编号格式

```
{项目缩写}-{分类}-{年份}-{序号}
```

| 字段     | 说明                       | 示例   |
| -------- | -------------------------- | ------ |
| 项目缩写 | 项目英文缩写，大写         | `VPP`  |
| 分类     | 文档类别缩写，大写         | `ARCH` |
| 年份     | 创建年份                   | `2026` |
| 序号     | 该分类下的顺序号，3 位数字 | `001`  |

### 2.2 分类缩写对照表

| 分类缩写      | 含义         | 示例文档                       |
| ------------- | ------------ | ------------------------------ |
| `ARCH`        | 架构设计     | 总体架构与设计理念             |
| `AGG`         | 聚合平台     | VPP聚合平台与智能台区管理      |
| `RETAIL`      | 电力零售     | 电力零售与合同能源管理         |
| `EVCS`        | 充电桩管理   | 充电桩管理系统与V2G            |
| `TRADING`     | 电力交易     | 电力交易与报价引擎             |
| `SETTLEMENT`  | 智能结算     | 智能结算与偏差管理             |
| `SECURITY`    | 系统安全     | 系统安全合规与部署             |
| `APPENDIX`    | 附录         | 附录系列文档                   |
| `HEMS`        | 家庭能源管理 | 家庭能源管理系统技术方案       |
| `STD`         | 标准规范     | 能量路由器标准草案             |
| `FEASIBILITY` | 可行性分析   | 平台方案商业技术可行性分析报告 |
| `REPORT`      | 研究报告     | country_report、投资评估报告   |
| `BRAINSTORM`  | 头脑风暴     | 分阶段实施方案头脑风暴         |

### 2.3 编号分配规则

- 每个分类的序号从 `001` 开始，按创建时间递增
- 已废弃的文档编号不重复使用
- 文档编号一旦分配，在文档生命周期内保持不变

## 3. 版本号规范

### 3.1 版本号格式

采用 **SemVer 2.0** 原则：`主版本.次版本.修订号`

| 版本位     | 递增条件                                               | 示例              |
| ---------- | ------------------------------------------------------ | ----------------- |
| **主版本** | 重大架构调整、范式转换、不兼容的变更                   | `1.0.0` → `2.0.0` |
| **次版本** | 新增章节、功能模块、向下兼容的内容扩展                 | `1.0.0` → `1.1.0` |
| **修订号** | 勘误、格式调整、措辞优化、引用更新，不改变文档实质内容 | `1.0.0` → `1.0.1` |

### 3.2 版本状态

| 状态         | 说明                                       | 允许操作           |
| ------------ | ------------------------------------------ | ------------------ |
| `draft`      | 草稿阶段，内容可任意修改                   | 任意修改           |
| `review`     | 审查阶段，冻结内容，仅允许修订号级别的修改 | 仅修订号递增       |
| `published`  | 已发布，内容不可变                         | 不可修改，仅可废弃 |
| `deprecated` | 已废弃，被新版本或新文档取代               | 不可修改           |

### 3.3 版本晋升流程

```
draft ──→ review ──→ published ──→ deprecated
   ↑          │
   └──────────┘ (退回修改)
```

- **draft → review**：内容基本完成，提交审查
- **review → published**：审查通过，发布定稿
- **published → deprecated**：被新版本取代
- **review → draft**：审查发现问题，退回修改

## 4. 文件头部元数据规范

### 4.1 标准模板

每份工作文档必须在文件开头包含以下元数据块：

```markdown
---
document_id: VPP-ARCH-2026-001
version: 1.0.0
status: published
created_date: 2026-05-25
last_modified: 2026-05-26
author: [作者/团队]
change_summary: |
  初始版本
---
```

### 4.2 字段说明

| 字段             | 必填 | 说明                                                      |
| ---------------- | ---- | --------------------------------------------------------- |
| `document_id`    | ✅   | 文档编号，遵循 §2 规范                                    |
| `version`        | ✅   | 当前版本号，遵循 §3 规范                                  |
| `status`         | ✅   | 文档状态：`draft` / `review` / `published` / `deprecated` |
| `created_date`   | ✅   | 首次创建日期，格式 `YYYY-MM-DD`，创建后不变               |
| `last_modified`  | ✅   | 最后修改日期，每次版本变更时更新，格式 `YYYY-MM-DD`       |
| `author`         | ✅   | 文档作者或责任团队                                        |
| `change_summary` | ✅   | 本次版本变更的简要说明，使用 YAML 多行字符串（`\|`）      |

### 4.3 兼容性说明

对于已有文档头部表格的文档（如 VPP 系列），建议逐步迁移到新格式。过渡期内，表格格式和 YAML front matter 格式可并存，但必须包含以下必填字段：

- 文档编号（document_id）
- 版本号（version）
- 制定日期（created_date）
- 最后修改日期（last_modified）

## 5. 变更历史规范

### 5.1 变更历史表格

每份文档应在末尾（或附录中）维护变更历史表格：

```markdown
---

## 变更历史

| 版本  | 日期       | 修改人 | 变更说明                                  |
| ----- | ---------- | ------ | ----------------------------------------- |
| 1.0.0 | 2026-05-25 | [作者] | 初始版本                                  |
| 1.1.0 | 2026-05-26 | [作者] | 新增第X章：XXX；更新附录C安全加固方案     |
| 1.1.1 | 2026-05-27 | [作者] | 修正第3章图例编号错误；更新引用标准版本号 |
```

### 5.2 变更说明撰写规范

| 变更类型 | 说明格式示例                                          |
| -------- | ----------------------------------------------------- |
| 新增     | `新增第X章：章节标题`                                 |
| 修改     | `更新第X节：修改内容简述`                             |
| 删除     | `删除第X节：删除原因`                                 |
| 修正     | `修正第X章图例编号错误`                               |
| 引用更新 | `更新引用标准版本号：GB/T XXXX-202X → GB/T XXXX-202Y` |
| 安全加固 | `更新附录C：安全加固方案v2.0`                         |

## 6. 文件命名规范

### 6.1 命名格式

```
{序号}_{文档标题}_{版本号}.md
```

| 组成部分 | 说明                         | 示例                 |
| -------- | ---------------------------- | -------------------- |
| 序号     | 2位数字，按逻辑顺序排列      | `01`                 |
| 文档标题 | 简洁描述性标题，中文         | `总体架构与设计理念` |
| 版本号   | 可选，用于区分同标题不同版本 | `v1.0.0`             |

### 6.2 示例

```
01_总体架构与设计理念.md
02_VPP聚合平台与智能台区管理.md
附录C_OpenADR2.0与电力专用通道对比说明.md
家庭能源管理系统_HEMS_技术方案_v1.0.0.md
```

> **注意**：文件名中的版本号仅作为快速标识，**文档头部元数据中的版本号是权威来源**。

## 7. 与平台 Release 治理的集成

### 7.1 集成方式

工作文档可选择性地纳入平台 Release 治理体系，通过以下方式：

1. **在 `active-release.yaml` 中注册**：在 `active_components` 下新增 `output_documents` 字段，列出纳入治理的文档清单
2. **Release Manifest 记录**：在 Release Manifest 中记录文档版本快照
3. **Git tag 关联**：重要文档版本发布时，可打 Git tag 关联

### 7.2 注册示例

```yaml
# active-release.yaml 新增字段
active_components:
  output_documents:
    - id: VPP-ARCH-2026-001
      path: OUTPUT/VPP_综合技术方案/01_总体架构与设计理念.md
      version: 2.1.0
      status: published
    - id: VPP-AGG-2026-002
      path: OUTPUT/VPP_综合技术方案/02_VPP聚合平台与智能台区管理.md
      version: 1.0.0
      status: published
```

### 7.3 集成级别

| 级别 | 说明                         | 适用场景                   |
| ---- | ---------------------------- | -------------------------- |
| L0   | 不纳入治理，自由管理         | 草稿、临时笔记             |
| L1   | 仅文档编号和版本号注册       | 常规工作文档               |
| L2   | 注册 + Release Manifest 记录 | 重要技术方案、正式发布文档 |
| L3   | 注册 + Manifest + Git tag    | 对外交付、合同附件级文档   |

## 8. 工作流程

### 8.1 创建新文档

```bash
# 1. 分配文档编号（按分类递增）
# 2. 创建文件，填写头部元数据
# 3. 设置版本号为 1.0.0，状态为 draft
# 4. 编写内容
# 5. 提交 Git
```

### 8.2 修改现有文档

```bash
# 1. 更新 last_modified 日期
# 2. 根据变更类型递增版本号
# 3. 更新 change_summary
# 4. 在变更历史表格末尾追加记录
# 5. 提交 Git
```

### 8.3 发布文档

```bash
# 1. 确认内容完整
# 2. 将状态从 draft 改为 published
# 3. 如需纳入平台治理，更新 active-release.yaml
# 4. 提交 Git，可选打 tag
```

## 9. 角色与责任

| 角色       | 职责                                 |
| ---------- | ------------------------------------ |
| **作者**   | 创建文档、维护版本号、更新变更历史   |
| **审核者** | review → published 阶段审核内容      |
| **维护者** | 管理文档编号分配、监督规范执行       |
| **系统**   | 自动检查文档头部元数据完整性（可选） |

## 10. 与现有规范的关系

| 现有资产                     | 与本规范的关系                                   |
| ---------------------------- | ------------------------------------------------ |
| `docs/release_governance.md` | 平台资产版本治理，本规范是其在工作文档领域的扩展 |
| `config/active-release.yaml` | 运行时指针，可扩展记录工作文档版本               |
| `config/releases/*.yaml`     | Release Manifest，可记录工作文档版本快照         |
| `CHANGELOG.md`               | 平台变更日志，工作文档变更可选择性记录           |
| Git commit                   | 所有文档变更通过 Git 管理                        |
