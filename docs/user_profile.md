### 2026-05-08: 建立跨对话记忆系统

- **内容**: 创建了 `docs/user_profile.md` 和 `config/session-tracking.yaml`
- **决策**: 建立用户配置 + 会话跟踪的双重记录系统

### 2026-05-11: 明确"理解意图"的最佳方案 + 执行后总结归纳机制

- **内容**: 讨论了 AI 如何充分理解用户意图，以及执行任务后的总结归纳机制
- **关键决策**:
  1. AI 应优先通过项目文件结构（README、model_context、active-release）建立宏观理解，而非直接开始编码
  2. 用户偏好 AI 提供"项目详细描述"而非"详细代码"——即架构和设计意图优先于实现细节
  3. 建立"执行后总结归纳"机制：每次重要任务完成后，AI 必须更新 `docs/user_profile.md` 的会话历史摘要
  4. 对于涉及架构决策的复杂任务，额外创建或更新 `docs/retrospective_*.md`
- **发现的偏好**:
  - 用户希望 AI 在理解意图时，先展示对项目的整体理解（描述性），让用户验证后再行动
  - 用户认为"总结归纳"比"完成任务本身"更重要——没有总结，AI 无法在后续对话中积累对用户的理解
  - 用户偏好 AI 主动提供选项式澄清（2-5 个选项），而非让用户写长文本
  - 用户重视"从历史中学习"——`retrospective_20260511.md` 就是一个典型例子
- **文档变更**: 本次更新了 `docs/user_profile.md`（会话历史摘要）
- **状态**: ✅ 完成

### 2026-05-12: 澳洲输电CGT问题深度分析

- **内容**: 用户要求分析一篇关于澳洲输电补偿金CGT问题的文章。任务从简单的"文章分析"逐步演变为多层次的深度分析项目，最终产出4份文档（市场分析报告、方法论框架、情景推演、博客文章）。
- **关键决策**:
  1. 博客文章默认采用专业分析风格（技术/金融从业者视角），而非轻松叙事风格
  2. 用户擅长且喜欢深度追问，每次反馈都在引导分析向更深层次发展
  3. 用户关注"制度设计"和"利益分配"，而非表面现象或个人道德评判
  4. 用户接受迭代式工作——先出初版，根据反馈不断深化
- **新增偏好确认**:
  - 默认采用专业分析风格（结构化输出 + 量化指标 + 概率分析）
  - 博客类任务需先确认目标受众和风格要求
  - 需要主动管理任务边界，避免无限扩展
  - 用户喜欢多情景推演和利益相关方分析
- **写作风格偏好（从对比学习中确认）**:
  - 标题要有记忆点（如"阿喀琉斯之踵"类隐喻），避免纯描述性标题
  - 开篇第一段直接给出核心判断，不铺垫背景
  - 每段只传递一个要点，提升扫读性
  - 使用标准金融术语（Beta系数、DCF模型、蒙特卡洛模拟、帕累托最优），避免自创术语
  - 投资建议用"做多/做空"等明确信号，而非"增配/减配"等中性表述
  - 篇幅控制在1500字左右（阅读时长约8分钟），避免超过2000字
  - 章节层级不超过两级（一、二、三 + 加粗小标题），不使用多级编号
  - 标注阅读时长，帮助读者预判投入
- **文档变更**: 创建了 `docs/retrospective_20260512.md`（详细复盘），更新了 `docs/user_profile.md`
- **状态**: ✅ 完成
